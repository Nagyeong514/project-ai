\* Qwen3-14B 열은 **2026-07-11 추가 실행**(잡 2596, `evaluate_llm_realdb_qwen3_14b.py`) —
STEP5 융합 채택 모델(텍스트 전용)을 답변 생성 역할로도 동일 조건(같은 SYSTEM_PROMPT·

`think:false`로 차단(7/7 정상, `<think>` 유출 0건). 원 3종과 실행 시점만 다름.
답변 7건 전문은 `llm_benchmark_results_realdb_qwen3_14b.json`,
상세 분석은 `평가보고서_realdb_qwen3_14b.md` 참조.

- VRAM은 모델 전환 시 언로드(`keep_alive=0`) 후 측정한 **모델별 단독 점유값** (기존 방식 유지).
- Throughput은 Ollama 응답의 `eval_count / eval_duration` 기반 **순수 생성 속도** —
  모델 크기 역순(4B > 8B > 8.8B)으로 나왔고 케이스 간 편차가 매우 작다(모델별 ±2 tok/s 이내).
- 평균 Latency 순서가 Throughput과 다른 이유: Latency는 답변 길이가 섞인 round-trip이라
  **답변을 길게 쓰는 경향**이 지배한다. Qwen은 절차를 4~5단계로 풀어 쓰는 경향이 있어
  Latency 1위(최장)이고, Llama는 가장 짧게 답해 Latency 최단이다.
- VRAM/모델별 상대 순위는 기존 실험과 동일(7.0/5.1/3.7 GiB 재현) — 측정 방식 일관성 확인.

## 4. 정성 평가 참고 메모 (채점 아님 — 전문 검토 시 볼 지점)

이번 실험은 충실도 채점을 스킵했으므로 아래는 판정이 아니라 **관찰 포인트**다.

### 4-1. 컨텍스트 충실도에 따라 모델 차이가 갈린다

- **컨텍스트가 충실한 질의(q1~q4, 절차가 구조화된 레코드)**: 세 모델 모두 핵심을 정확히
  전달 — 모델 간 차이는 문체·상세도 수준.
- **컨텍스트가 빈약한 질의(q5/q6, 절차가 발화 한 줄)**: 세 모델 모두 절차를 재구성하려
  들었고 여기서 크게 갈렸다. **Qwen만 인용·출처·취지를 유지**(발화를 `(발화)` 라벨/따옴표로
  구분 인용), Llama는 화자 역할 오해(q5)와 출처 소실(q6), Gemma는 원문 왜곡(q5 조건 반전,
  q6 "화면 5인식" 뭉갬). → **원천 암묵지의 절차가 빈약하면 LLM이 메꾸려 든다** — 발화
  인용형 레코드는 STEP5에서 절차를 더 구조화하거나, 답변을 검색 조립문 그대로 읽는 쪽이
  안전. 기존 실험의 "Qwen 충실도 우위" 결론과 방향이 일치하는 실데이터 근거.

### 4-2. 그 외 관찰

1. **무관 질의(q7) 방어는 3모델 모두 성공** — 환각 없이 거부. 단 출처 줄 처리가 갈림:
   Qwen·Llama는 시스템 프롬프트의 플레이스홀더를 그대로 복사, Gemma만 "정보 없음" 처리.
   → 기존 보고서 §4 결론 "출처 줄은 검색 메타데이터로 후처리 생성"이 실DB에서도 재확인됨.
2. **출처 표기 자체는 크게 개선** — 관련 질의 18건(6질의×3모델) 중 Llama q6 1건만
   플레이스홀더로 이탈, 나머지는 실제 파일명·타임스탬프를 정확히 표기. 컨텍스트가 `출처:`
   줄을 포함한 조립 템플릿이라 모델이 베낄 원본이 명확해진 효과로 보임(기존 실험에서
   Qwen 영상ID 누락 8/19건과 대조).
3. **Llama 문자 오염 재발**: q3 "ảnh상칠"(베트남어 문자) — 기존 실험의 한자 노출("乾燥")과
   같은 계열. TTS로 읽히면 그대로 노출되는 손상. 어색한 표현("조심들게", "고정된지")도 간헐.
4. **Qwen q1/q2**: 컨텍스트의 diagnostic_steps(관찰 동작 나열)를 재배열해 그럴듯한 확인
   절차로 만들었는데, 원문 동작의 취지가 애매하게 변형된 단계가 섞임("잠그는 방향에서 약간
   옆으로 미끄러뜨려") — 관찰 로그 기반 레코드 특유의 위험(동작 나열 → 지시문 변환 왜곡).
5. **Llama의 "(발화)" 라벨 노출**(q3): 컨텍스트 내부 표기를 절차 문장에 그대로 복사 —
   TTS 가독성 저해. Gemma도 q6에서 동일.

## 5. 결론

- **정량(속도·자원)만 보면**: Throughput·VRAM은 Gemma-3-4B(76.4 tok/s, 3.7 GiB),
  round-trip은 Llama-3.1-8B(2.77초)가 우위. Qwen3-VL은 셋 중 가장 무겁고 느리다.
- **답변 품질의 결정 변수는 모델보다 원천 레코드의 절차 충실도**였다: 절차가 구조화된
  레코드(q1~q4)에서는 세 모델이 사실상 동급, 발화 한 줄짜리 레코드(q5/q6)에서만 Qwen이
  단독으로 버텼다(§4-1). 기존 실험 결론(충실도 근거 Qwen 채택 + 시스템 방어 4종 전제)을
  뒤집을 근거는 없으며, 오히려 실데이터에서 같은 방향으로 재확인됐다.
- 실DB 파이프라인 관점의 소득: ① 검색 top-1 6/6 적중과 무관 질의 차단(sim 0.40)이
  실데이터로 재확인 ② 조립 템플릿 컨텍스트가 출처 표기 품질을 크게 끌어올림(§4-2)
  ③ 발화 인용형 레코드의 절차 빈약이 LLM 재구성 왜곡을 유발(§4-1) — STEP5 생성 단계로
  피드백할 안건.
