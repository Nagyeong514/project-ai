## 0. 한눈에 보는 시스템 개요

이 파이프라인은 스마트글래스(1인칭 시점)로 촬영한 PC 수리 영상 1개를 입력받아, **STT(음성)** 와 **VLM(영상 관찰)** 두 갈래로 독립적으로 처리한 뒤 **LLM 융합** 단계에서 하나의 "암묵지 후보(tacit knowledge candidate)" JSON으로 합치는 5단계 오케스트레이션이다(`tacit_pipeline/orchestrator.py:37-224`의 `Pipeline` 클래스).

```
영상(.mp4)
  ├─[음성 갈래] STT(Whisper) → transcript 정제(정규화+반복태깅)
  └─[영상 갈래] ffmpeg 프레임 추출(YOLO·VLM 공용) → YOLO 검출(위치힌트) → VLM 관찰(observations)
                    └──────────────┬──────────────┘
                          타임스탬프 윈도우 정렬(±4초)
                                   ↓
                      LLM 융합(Qwen2.5) → 암묵지 후보 JSON (스키마 v1.3)
```

핵심 설계 철학은 코드 주석에 반복적으로 등장하는 세 문장으로 요약된다:
- "VLM은 **눈**이다. 관찰만 한다." (`prompts/vlm_observation.py:4`)
- "타임스탬프가 뼈대다. 모든 중간 산출물은 공통 초(float) 단위로 정규화." (`schema/intermediate.py:4`)
- "이 파이프라인은 후보 **생성**까지만 담당한다. 판별/검증은 다음 단계." (`tacit_pipeline/__init__.py:3`)

### 1-2. 데이터 처리 단위

- **최상위 단위 = 영상 1개(파일) 단위 순차 처리.** `Pipeline.run(video_path)`(`orchestrator.py:86-170`) 한 번 호출이 영상 1개를 처음부터 끝까지 처리한다. 멀티스레딩·멀티프로세싱·비동기 처리는 코드 어디에도 없다(`asyncio`, `threading`, `multiprocessing` import 전무).
- **다중 영상 처리 = 단순 for 루프, 모델은 1번만 로드.** `run_all_clips.py:23-36`이 `Pipeline` 객체를 한 번만 생성하고 `for video in VIDEOS: pipe.run(video)`로 4개 클립을 순차 처리한다. 주석(`run_all_clips.py:2-4`): "`run.py`를 4번 따로 부르면 STT/YOLO/VLM/LLM을 매번 새로 로드해야 해서 비효율적" — **모델 재로딩 방지가 목적이지, 배치 병렬 추론은 아니다.** 클립 하나가 실패해도 `try/except`(`run_all_clips.py:30-36`)로 잡아 다음 클립으로 넘어가고, 마지막에 `[SUMMARY]`로 성공/실패를 모아 출력, 실패가 하나라도 있으면 `sys.exit(1)`.
- **VLM 단계 = "영상 1개 = 1회 멀티모달 추론 호출".** 프레임을 하나씩 모델에 넣는 게 아니라, ffmpeg로 뽑은 프레임 전체 리스트(예: CLIP1 30프레임)를 `messages`의 `{"type": "video", "video": frames}` 한 덩어리로 넣어 `_generate_mm()`(`vlm_qwen.py:209-223`) 한 번만 호출한다 — "네이티브 비디오 모드"라 불리는 이유.
- **YOLO 단계 = 프레임별 순차 `predict()` 호출(배치 아님).** `detect()`(`detector_yolo.py:78-107`)는 `for fr in frames: ... self._model.predict(source, ...)`로 **프레임마다 개별 추론**한다. ultralytics는 리스트를 한 번에 batch predict 할 수 있지만 이 코드는 그렇게 안 짜여 있다 — 성능상 미최적화 지점(면접에서 "왜 배치로 안 돌렸나" 질문 시 정직하게 답할 수 있는 포인트).
- **LLM 융합 = 영상 전체의 정렬 윈도우를 한 번에 하나의 JSON 프롬프트로.** `_serialize(windows)`(`llm_fusion.py:121-146`)가 그 영상의 모든 `AlignedWindow`를 리스트로 직렬화해 **한 번의 채팅 요청**(`build_fusion_messages`)으로 LLM에 넘긴다 — 윈도우별 개별 호출이 아니라 "영상 1개 = LLM 호출 1회"(단, 스키마 검증 실패 시 최대 `max_retries+1`회 재호출, §3-9).

## 2. VLM 및 STT 프롬프트 엔지니어링 디테일

### 2-1. (Q3) VLM 프롬프트 원문과 제약 조건

**System Prompt** (`prompts/vlm_observation.py:25-52`, `VLM_OBSERVATION_SYSTEM_PROMPT` 원문 그대로):

```text
당신은 1인칭(스마트글래스) 수리 영상의 '관찰 기록기'다. 당신은 눈이며, 오직 보이는 사실만 적는다.

[절대 규칙]
1. 관찰만 한다. 해석·추론·의도파악·진단 결론·여러 동작 묶기를 절대 하지 않는다(그건 다음 단계의 일).
2. 추상 동사 금지: "확인한다 / 점검한다 / 검사한다 / 진단한다" 같은 말을 쓰지 마라.
   → 눈에 보이는 구체 동작으로 적는다.
   (나쁨) "RAM을 점검한다"   (좋음) "오른손 검지와 중지로 RAM 모듈 상단 양끝을 집어 슬롯에서 위로 들어올린다"
3. 손 동작은 '어느 손 / 어느 손가락이 / 무엇을' 단위로 분리해 적는다(AR 시점의 세밀한 손동작이 핵심).
4. 측정값(각도·거리·치수 등)을 추정하지 마라. 보이지 않는 수치를 지어내지 마라.
   단, 셀 수 있는 것(예: LED 점멸 '횟수')은 관찰 사실로 적어도 된다.
5. 전원 버튼 LED는 색과 깜빡임 '횟수'만 적는다(예: "황색 1회 깜빡인 뒤 백색 3회 깜빡인다").
   그것이 무슨 의미인지(원인/진단)는 절대 적지 마라.
6. 보이지 않는 도구·부품·글자·말은 적지 마라. 화면에 실제로 보이는 것만.

[출력 형식 — 이 JSON만 출력. 배열 밖 텍스트 절대 금지]
{
  "observations": [
    {
      "timestamp": "<주어진 값 그대로>",
      "actor": "<오른손|왼손|양손|시선 등>",
      "action": "<눈에 보이는 단일 구체 동작 한 문장>",
      "objects_visible": ["<보이는 객체명>", ...]
    }
  ]
}
행동 하나당 entry 하나. 동시 동작이면 timestamp를 같게 두고 entry를 나눈다.
```

**User Prompt는 4개 블록을 `"\n\n".join(blocks)`로 조립**한다(`build_video_observation_messages()`, `prompts/vlm_observation.py:118-141`):
1. (조건부) `[고정 사실] 이 영상에 등장하는 부품은 다음과 같다(이 식별을 신뢰하라): RAM, RAM_slot, ...` — `injected_parts`가 있을 때만.
2. `출력 형식 예시(이 형식을 정확히 따른다):` + few-shot JSON 블록(`_fewshot_block()`).
3. `영상 전체를 시간순으로 보며, 보이는 동작을 관찰 규칙대로 하나씩 기록하라. ... observations 배열 JSON만 출력. 배열 밖 텍스트 금지.`
4. (실제 호출부 `vlm_qwen.py:171-172`에서 런타임에 추가) 영상 길이 문구 + `timestamp는 영상 시작(00:00:00) 기준 대략적인 초 단위로 적어라.`

**핵심 제약/역할 분석**:
- **역할 분리(관찰 vs 해석)**: 시스템 프롬프트 첫 줄부터 "당신은 눈이며"로 못박고, LED 규칙(규칙 5)이 이 철학의 시금석이다 — VLM은 "횟수"만 세고 "무슨 의미인지"는 절대 금지. 의미 해석(LED 진단 코드표)은 `llm_fusion_prompt.py`에만 존재(§2-3).
- **추상동사 금지 + Good/Bad 예시 페어**: 프롬프트 안에 나쁜 예/좋은 예를 직접 대비시켜(few-shot이 아니라 규칙 설명 안의 인라인 대비) 모호함을 줄임.
- **수치 환각 금지 예외 조항**: "측정값 추정 금지"의 예외로 "셀 수 있는 것"만 허용 — 이는 LED 깜빡임 횟수 관찰을 살리면서 각도·거리 같은 순수 추정값 환각은 차단하는 정교한 이분법.
- **출력 형식 강제**: "배열 밖 텍스트 절대 금지"를 시스템 프롬프트와 유저 프롬프트 양쪽에 중복 명시(이중 강조).
- **Few-shot 3건**(`_FEWSHOT_EXAMPLES`, `prompts/vlm_observation.py:55-74`)이 담고 있는 기법: (a) 손가락 단위 분리 예("검지와 중지로"), (b) 도구 사용 예(지우개로 접점 세척), (c) LED 횟수만 관찰하는 예 — 세 예시가 각각 시스템 프롬프트의 규칙 3/6/5를 구체 사례로 못박는 구조.
- **의도적으로 숨기는 정보**: 모듈 docstring(`prompts/vlm_observation.py:17`)에 "촬영이 'RAM 탈거로 증상을 시뮬레이션'한 것이라는 사실은 모델에 절대 주지 않는다"고 명시 — VLM이 정답을 알고 관찰을 짜맞추는 leak을 원천 차단.
- **버전 2개 존재, 1개는 죽어있음**: `build_observation_messages()`(단일 프레임 + YOLO 검출 리스트를 프롬프트에 텍스트로 나열하는 구버전, `prompts/vlm_observation.py:81-115`)는 `prompts/__init__.py:4,8`에서 export까지 되어 있지만 **실제 파이프라인 어디에서도 호출되지 않는 죽은 코드**다. 오케스트레이터/어댑터는 전부 `build_video_observation_messages()`(네이티브 비디오, 프레임 텍스트 나열 없음)만 쓴다. 과거 "프레임별 개별 프롬프트" 설계에서 "영상 전체 1콜" 설계로 전환하며 남은 흔적.
- **실측으로 깎인 제약**: `vlm_qwen.py:168-170` 주석에 "2026-07-02 실측: 55개 시각을 전부 나열해 '이 중에서 골라라'라고 강제하면 모델이 observations=[]로 얼어붙는다"는 실패 경험이 남아있고, 그래서 현재는 정확한 그리드 선택을 강제하지 않고 "대략적인 초 단위"로 완화한 뒤 `snap_to_grid()`(§3-9)로 사후 보정하는 방식을 택했다.

### 2-2. (Q4) STT 전후 프롬프트/보정 로직

**STT 자체에는 "프롬프트"가 없다** — Whisper 계열은 자유 텍스트 프롬프트를 받는 구조가 아니라 디코딩 하이퍼파라미터로 제어한다. 이 코드가 STT 품질을 통제하는 방식은 3단:

1. **디코딩 파라미터 자체가 "환각 억제 지침" 역할**: `condition_on_previous_text=False`(`stt_whisper.py:41`, `config.yaml:52`) — 이전 세그먼트를 컨텍스트로 안 씀으로써 반복 루프/환각 전파를 차단. `word_timestamps=False`(`stt_whisper.py:105`, 하드코딩, config로 노출 안 됨)로 단어 단위 타임스탬프는 아예 요청 안 함(세그먼트 단위만).
2. **VAD로 무음 구간 자체를 스킵**: `vad_filter=True`(faster-whisper 내장) — 프롬프트가 아니라 오디오 레벨 전처리지만, 목적은 "무음에서 헛소리(환각)를 만들지 않게" 하는 것이라 실질적으로 STT의 "지침" 역할.
3. **사후 텍스트 보정(진짜 "STT 이후 로직")은 `transcript_refine.py`의 `NormalizeRefiner`가 담당**하며, 두 가지 결정적(deterministic) 작업만 한다(정규식 기반, LLM 아님):
   - **영어/기술용어 정규화**: `resources/en_normalization.json`의 사전으로 오인식 치환. 실제 활성 항목은 `"마더보이드": "motherboard"`, `"마더보드": "motherboard"`, `"메인보드": "motherboard"` 3건뿐이고, `_candidates` 아래 `"램":"RAM"`, `"바이오스":"BIOS"`, `"디램":"DRAM"` 등 13개는 **"아직 실측 안 됨"이라 비활성** 상태로 대기 중이다(파일 주석: "추측만으로 활성화 금지 — 잘못된 치환이 원문 훼손"). `_normalize()`(`transcript_refine.py:69-74`)는 **긴 키부터 정렬해 치환**해 부분매칭 충돌을 막는다(`sorted(self._norm, key=len, reverse=True)`).
   - **환각 상투구 탐지 + 반복 탐지**: `DEFAULT_HALLUCINATION_PHRASES`(`transcript_refine.py:32-40`) 원문 그대로: `["다음 영상에서 만나요", "다음 영상에서 뵙겠습니다", "시청해 주셔서 감사합니다", "감사합니다", "구독과 좋아요", "구독", "아멘"]` — 이 리스트는 "무음/잡음 구간에서 Whisper가 흔히 만들어내는 상투구"를 4개 클립 실측으로 관측해서 만든 denylist다. **텍스트를 지우지 않고** `repeat_hallucination=True`로 태깅만 하고(`_norm_key()`로 정규화 후 매칭), 직전 발화와 완전히 동일해도 같은 플래그가 붙는다(`refine()`, `transcript_refine.py:76-105`).
   - **중요한 설계 결정**: "근거성(인과/조건/주의) 판단은 여기서 안 한다"는 주석(`transcript_refine.py:10-12`)과 함께, 그 이유로 "한국어 구어체(~하면 됩니다, ~나면 ~거에요)를 정규식이 0건 잡음 — 정규식 근거판단은 폐기"라는 **실측 실패 기록**이 남아있다. 즉 애초엔 정규식으로 "이 발화가 노하우인가"를 걸러내려 했으나 실패했고, 이 판단을 통째로 후속 LLM 융합 단계로 위임하도록 아키텍처를 바꾼 흔적.

### 2-3. (Q5) VLM 프롬프트와 STT 결과물의 결합 지점

결합은 정확히 **오케스트레이터의 `[5/5] LLM 융합` 단계 진입 직전**, 3단계로 일어난다.

1. **정렬(Alignment)** — `orchestrator.py:143`: `windows = self.aligner.align(actions, transcript, flat_dets)`. `WindowAligner.align()`(`aligner.py:36-84`)이 VLM `ActionDescription` 리스트와 STT `Utterance` 리스트를 **초 단위 시간축에서 병합**한다. 전략은 "행동을 앵커로 ±`window_sec`(기본 4.0초) 구간 안의 발화를 묶고"(`aligner.py:49-66`), "어느 행동 윈도우에도 안 걸린 발화는 별도 `utterance_only` 윈도우로 수거"(`aligner.py:68-79`)한다. 이 결과 `AlignedWindow.case` 프로퍼티(`schema/intermediate.py:157-168`)가 `"fusion"|"action_only"|"utterance_only"|"empty"` 4종으로 분류된다.
2. **직렬화(Serialize)** — `llm_fusion.py:121-146`의 `_serialize()`가 각 윈도우를 `{"case", "window_start"(HH:MM:SS), "window_end", "actions":[...], "utterances":[...]}` 형태의 순수 dict 리스트로 변환한다. 이때 VLM 쪽은 `action`/`objects_visible`, STT 쪽은 `raw_text`/`normalized_text`/`repeat_hallucination`이 나란히 들어간다.
3. **프롬프트 삽입(Inject)** — `build_fusion_messages(video_id, windows_payload)`(`prompts/llm_fusion_prompt.py:130-147`)가 이 payload 전체를 `json.dumps(..., indent=2)`로 문자열화해 **user 메시지 본문에 통째로 박아 넣는다**(`f"{json.dumps(windows_payload, ...)}"`). 즉 VLM/STT 결과가 결합되는 지점은 API 파라미터가 아니라 **LLM 채팅 프롬프트의 user turn 텍스트 안**이다.

이후 `QwenLLMFusion.fuse()`(`llm_fusion.py:148-166`)가 이 메시지로 LLM을 호출하고, 결과를 파싱·검증해 `TacitKnowledgeDocument`로 반환한다.

## 3. '추구미 JSON' 양식 및 포맷 강제화 전략

### 3-1. (Q7) 목표 출력 스키마 파일 전수 분석

이 프로젝트의 "원하는 출력 형태를 정의한 JSON"은 코드 안에 **3개 층위**로 존재한다.

**(A) 최종 산출물 스키마 — `tacit_pipeline/schema/tacit_schema.py`** (Pydantic 모델, `SCHEMA_VERSION = "1.3"`, `tacit_schema.py:22`). 파일 자체 docstring이 "단일 진실 공급원(single source of truth)"이라 명시(`tacit_schema.py:2`). 구조:

```
TacitKnowledgeDocument              # 영상 1개 = 파일 1개
├─ schema_version: "1.3"
├─ video_id: str
└─ candidates: List[TacitKnowledgeCandidate]     # 암묵지 후보 N건
     ├─ id: str                     # [자동] "tk_<video_stem>_<NNN>"
     ├─ schema_version
     ├─ metadata: Metadata          # [자동] LLM은 건드리지 않음
     │    ├─ scenario_id            # [자동]
     │    ├─ equipment/task/keywords/scenario_title   # [LLM, 현재 실사용 데이터에선 전부 null/[])
     │    └─ source: Source
```

### 3-2. (Q8) VLM/LLM이 JSON 구조를 깨지 않게 만드는 장치

이 코드는 **API 레벨의 JSON mode(예: OpenAI `response_format`)를 전혀 쓰지 않는다.** `transformers.generate()`/`vllm`류 로컬 추론 API에는 그런 강제 기능이 없기 때문에, 전부 **프롬프트 강제 + 후처리 파싱**으로 대체한다.

1. **프롬프트 내 이중/삼중 형식 강제 문구**: "이 JSON만 출력. 배열 밖 텍스트 절대 금지"(시스템, `vlm_observation.py:40`), "JSON만 출력"(유저, `vlm_observation.py:109,136`), LLM 쪽은 "설명 문장 금지"(`llm_fusion_prompt.py:103`).
2. **Few-shot 예시를 프롬프트 안에 실제 JSON 텍스트로 박아넣기** — VLM은 `_fewshot_block()`(3건 예시), LLM은 시스템 프롬프트 맨 끝에 정확한 스키마 스켈레톤 JSON(`llm_fusion_prompt.py:108-126`)을 그대로 노출.
3. **생성 파라미터로 반복/발산 억제**: `repetition_penalty=1.2`(VLM, "짧은 영상 동일 블록 무한반복 억제" 주석), `do_sample=False`(그리디 — "재현성, 프롬프트 실험 필수").
4. **`apply_chat_template(..., do_sample_frames=False)`**(`vlm_qwen.py:214-216`) — JSON 포맷과 직접 관련은 없지만, "transformers가 55프레임을 24fps로 오인해 4프레임만 반영하는" 버그를 우회해 **VLM이 관찰할 프레임 자체가 누락되지 않게** 강제하는 장치(간접적으로 `observations: []` 출력 방지).
5. **메타데이터를 통째로 LLM 책임에서 제거**: 프롬프트에 "`metadata`는 시스템이 자동으로 채운다. 너는 채우지 마라 — `{}}`로 비워두거나 생략하라"(`llm_fusion_prompt.py:105-107`)고 명시하고, 실제로 `orchestrator._finalize_metadata()`(`orchestrator.py:172-193`)가 `id`/`scenario_id`/`source.*`를 **LLM 출력과 무관하게 코드가 덮어쓴다**. 이는 "LLM이 `'...'`(placeholder) 문자열을 그대로 뱉는 실수가 있었다"는 실측 실패를 근거로 한 설계(`llm_fusion_prompt.py:107`).

### 3-3. (Q9) 파싱/검증/재시도 로직

**VLM 쪽 파싱** — `QwenVLActionExtractor._parse_observations()`(`vlm_qwen.py:263-285`), 3단 폴백 체인:
1. 정상 경로: 코드펜스(` ``` `) 제거 → `text.find("{")`/`text.rfind("}")`로 바깥 JSON 객체만 잘라내 `json.loads()` → `observations` 배열 추출. **빈 배열 `[]`도 그대로 인정**(주석: "VLM이 관찰 없다고 한 것. 정크 금지" — 억지로 채우지 않음).
2. 실패 시 `_salvage_observations()`(`vlm_qwen.py:239-261`): **brace-매칭 알고리즘**으로 텍스트를 문자 단위로 순회하며 `{`를 스택에 push, `}`를 만나면 pop해서 그 구간만 개별 `json.loads()` 시도 — `max_new_tokens` 초과로 출력이 중간에 잘려도 **앞쪽의 완성된 관찰 객체들만 부분 복구**한다(`"action" in d`인 dict만 채택해 바깥 wrapper 객체 오인식 방지).
3. 최후 폴백: 그래도 하나도 못 건지면 원문 텍스트 전체를 `action` 필드에 넣은 관찰 1건으로 감싸 반환(`vlm_qwen.py:285`) — **완전 실패를 허용하지 않고 항상 뭔가는 반환**하는 설계.

**시간 정보 후처리**: `snap_to_grid(ts, grid)`(`vlm_qwen.py:34-42`) — 모델이 뱉은 timestamp는 "추정값"이므로 신뢰하지 않고, 실제 ffmpeg가 추출한 프레임 시각 그리드 중 **가장 가까운 값으로 강제 스냅**한다. 파싱 실패로 timestamp 자체가 없는 관찰은 `_even_grid_ts()`(`vlm_qwen.py:225-237`)로 "관찰 순서대로 그리드에 균등 배분"해 0초에 몰리는 것을 방지. 마지막으로 `sorted(out, key=lambda a: a.timestamp)`(안정 정렬, `vlm_qwen.py:198`)로 순서를 재정렬하고 몇 건이 이동했는지 `logger.warning`으로 남긴다.

**LLM 쪽 파싱 + Pydantic 검증 + 재시도** — `QwenLLMFusion.fuse()`(`llm_fusion.py:148-166`):
```python
for attempt in range(self.max_retries + 1):
    raw = self._infer(messages)
    try:
        doc = self._parse_and_validate(raw, meta.video_id)
        self._assign_ids(doc, meta.video_id)
        return doc
    except Exception as e:
        last_err = e
        messages = messages + [
            {"role": "assistant", "content": raw},
            {"role": "user", "content": f"JSON 스키마 검증 실패: {e}. 스키마를 정확히 지켜 JSON만 다시 출력하라."},
        ]
raise RuntimeError(f"LLM 융합 스키마 검증 {self.max_retries+1}회 실패: {last_err}")
```
`_parse_and_validate()`(`llm_fusion.py:187-198`)는 코드펜스 제거 → `find("{")`/`rfind("}")` 절단 → `json.loads()` → `TacitKnowledgeDocument.model_validate(obj)`(Pydantic 검증, 타입/필수필드/Enum값 불일치 시 여기서 예외 발생) 순. `max_retries=2`(config 기본)이므로 **최대 3회** 시도하고, 실패 시마다 **대화 히스토리에 실패한 응답 + 에러 메시지를 추가해 다음 시도의 컨텍스트로 사용**(멀티턴 self-correction). 3회 다 실패하면 `RuntimeError`로 파이프라인 전체가 죽는다 — VLM 쪽과 달리 **LLM 융합 실패는 관용적으로 처리하지 않음**(암묵지 후보는 스키마를 반드시 지켜야 하는 최종 산출물이기 때문).

**검증 통과 이후에도 끝이 아니다 — 코드 레벨 사후 교정 2종**(`orchestrator.py:150-167`, LLM을 신뢰하지 않는 "이중 방어"):
- **`enforce_evidence_grounding()`**(`tacit_schema.py:179-246`): LLM이 매긴 `evidence`/`timestamp`를 VLM 원본 관찰·STT 원본 발화의 **실제 타임스탬프와 직접 대조**해 코드가 강제로 고친다. 실제 사고 사례가 주석에 남아있다: "2026-07-02, CLIP3 — LLM이 t=2초의 VLM 관찰문을 그대로 베끼면서 timestamp만 1:01의 발화 시각으로 바꿔치기함." 대응 로직: (1) `action`이 실제 VLM 관찰문과 매칭되면 그 행동의 진짜 시각으로 `step.timestamp`를 덮어씀. (2) `source_utterance`가 입력 발화 목록에 없으면 "지어냄 의심"으로 `evidence`를 `action_only`로 강등하고 `source_utterance=None`. (3) 매칭은 되지만 실제 발화 시각이 `tolerance_sec`(=`aligner.window_sec`, 기본 4.0초) 이상 떨어져 있으면 "무관한 발화"로 판단해 역시 `action_only`로 강등. 문자열 매칭은 `_norm()`(`re.sub(r"[\s\W]+", "", s).lower()`, 8자 미만은 오탐 방지로 부분매칭 안 함)으로 정규화.
- **`cross_check()`**(`tacit_schema.py:129-176`): 강제 정정이 아니라 **경고 로그만** 남기는 약한 검증 — `evidence=utterance`인데 `source_utterance`가 VLM 관찰문과 일치하면 "관찰을 발화로 둔갑시킨 것으로 의심", 입력 발화 어디에도 없으면 "발화를 지어낸 것으로 의심" 등 6가지 위반 패턴을 문자열로 반환. 오케스트레이터는 이를 그냥 `print(f"[CROSS-CHECK]...")`로만 출력하고 파이프라인을 막지 않는다 — "후보는 빠짐없이 살리는 게 우선, 판별은 다음 팀 몫"이라는 주석의 설계 철학.

### 4-2. (Q11) 모델 입력 직전 변형 로직과 수치 기준

**영상 → 프레임(ffmpeg, `frame_extract.py:35-59`)**:
- 리사이즈: `scale='if(gt(iw,ih),{long_side},-2)':'if(gt(iw,ih),-2,{long_side})'`, `long_side=480`(기본) — **긴 변을 480px로 맞추고 짧은 변은 비율 유지(-2, 짝수 보장)한 스케일**. 즉 가로세로 어느 쪽이 긴지에 따라 조건부로 리사이즈 축을 바꾸는 ffmpeg 필터 표현식.
- 프레임레이트(fps) 샘플링: `fps={fps}` — 값 자체가 **길이 기준 조건부 분기**: `fps_for_duration()`(`vlm_qwen.py:97-100`)이 `duration_sec >= long_video_threshold_sec(120.0초)`면 `fps_long=0.15`(약 6.7초당 1프레임), 아니면 `fps_short=0.5`(2초당 1프레임)를 적용. 실측: CLIP1(199초, 긴 영상)은 `fps=0.15`로 30프레임 추출(`run_logs/all_clips_....log`: `duration=199s fps=0.15 → 30프레임`).
- JPEG 압축 품질: `jpeg_q=5`(ffmpeg `-q:v`, 기본값, 낮을수록 고화질 — ffmpeg qscale 척도).
- 타임스탬프 부여: `times = [i / fps for i in range(len(paths))]`(`frame_extract.py:58`) — **모델이 계산하는 게 아니라 그리드 인덱스에서 역산**한 값. 이 값이 이후 `snap_to_grid()`의 교정 기준(§3-3)이자 최종 스키마 timestamp의 원천.

**오디오 → STT(faster-whisper)**: 별도의 리샘플링/포맷 변환 코드는 없음(`.transcribe(video_path, ...)`에 영상 파일 경로를 그대로 넘김 — 오디오 추출은 faster-whisper/ffmpeg 내부에 위임). VAD `threshold=0.5`(Silero 임계값)만 노출된 수치 기준.

**YOLO 입력**: `imgsz=640`(정사각 리사이즈, ultralytics 표준), `conf=0.25`(신뢰도 임계), `iou=0.7`(NMS 임계, `config.example.yaml:34`에만 존재하고 실제 `config.yaml:13-21`엔 `iou` 키가 빠져 있어 `UltralyticsYOLODetector.__init__`의 기본값 `0.7`이 그대로 적용됨 — **운영 config가 예시 config보다 파라미터가 적은 사례**).

**샘플러 수치 기준**(`sampler_motion.py`, 단 본선 파이프라인에선 미사용 — §4-3 참고): `motion_thresh_px=15.0`(bbox 중심 이동 픽셀 임계), `contact_iou=0.05`, `contact_dist_px=80.0`(손-부품 근접 판정), `speech_pad_sec=0.5`(발화 구간 앞뒤 패딩), `min_gap_sec=0.4`(샘플 촘촘함 억제).

**정렬 윈도우 수치 기준**: `window_sec=4.0`(`aligner.py:32`) — "발화·행동은 동시에 안 일어난다"는 전제 하에 ±4초를 "같은 사건"으로 간주하는 임계.

**LED 관찰 → 진단 해석 매핑**(수치는 아니지만 결정론적 룩업): `LED_DIAGNOSTIC_TABLE`(`llm_fusion_prompt.py:23-30`) — "황색 1회+백색 3회 = 메모리/프로세서 문제" 등 Dell Precision 7920 전용 3개 규칙.

### 5-2. (Q14) 최종 데이터 저장 포맷과 경로 규칙

3종류 산출물이 **단계별로 별도 폴더**에 저장된다(오케스트레이터 주석: "결과물을 단계별 폴더로 분리해 한눈에 보기 쉽게 함").

| 산출물 | 경로 규칙 | 저장 함수 | 포맷 |
|---|---|---|---|
| STT transcript | `{transcript_dir}/{video_id}.json` (기본 `transcripts/CLIP1_정상조립과정.mp4.json`) | `WhisperTurboSTT._save()`(`stt_whisper.py:146-153`) | `Transcript.model_dump()` → `json.dump(..., ensure_ascii=False, indent=2)` |
| VLM 관찰 로그 | `{output_dir}/vlm_observations/{video_id}.observations.json` | `Pipeline._save_observations()`(`orchestrator.py:201-213`) | `{"video_id", "n_observations", "observations": [...]}` |
| 최종 암묵지 후보 | `{output_dir}/tacit_json/{video_id}.tacit.json` | `Pipeline._save()`(`orchestrator.py:215-223`) | `TacitKnowledgeDocument.model_dump()` |
| (중간) 프레임 jpg | `{output_dir}/_frames/frame_%04d.jpg` | `extract_frames()`(`frame_extract.py`) | 4자리 zero-padded 순번, 매 실행 시 이전 파일 삭제 후 재생성 |

파일명 규칙은 전부 **원본 영상 파일명(확장자 포함, `video_id = Path(video_path).name`, `orchestrator.py:49`)에 접미사만 붙이는 방식**이라 `CLIP3_재부팅시도 전까지.mp4`처럼 공백이 포함된 원본 파일명이 그대로 산출물 파일명에도 남는다(경로 이스케이프 처리 없음, OS 파일시스템이 공백을 허용하는 것에 의존). `id` 필드(스키마 내부)는 별도 규칙 `tk_{stem}_{i:03d}`(`orchestrator.py:187`, `stem`은 확장자 제거 + `-`→`_` 치환)로, 파일 시스템 경로와 JSON 내부 ID 네이밍이 서로 다른 정규화 규칙을 쓴다는 점이 디테일.

모든 JSON 저장은 `ensure_ascii=False`(한글 그대로 저장, `\uXXXX` 이스케이프 안 함) + `indent=2`(사람이 읽기 좋은 포맷)로 통일돼 있다.

**실제 저장된 데이터 현황(2026-07-02 실행분, `output/` 디스크 상태 확인)**: CLIP1=후보 4건/관찰 0건, CLIP2=후보 1건/관찰 0건, CLIP3=후보 1건/관찰 **11건**, CLIP4=후보 1건/관찰 0건. ⚠️ 이 관찰 0건 데이터 대부분은 **VLM 관찰 0건 버그(§2-1, `do_sample_frames` 문제)가 고쳐지기 전에 생성된 산출물**이며, 코드(`vlm_qwen.py`)는 이미 수정 완료된 최신 상태다 — 즉 디스크의 이 JSON들을 재실행하면 관찰 건수가 달라질 수 있다는 점을 면접에서 "지금 코드 상태 vs 지금 디스크 산출물"을 구분해 설명할 수 있어야 한다.

## 6. 면접용 구조적 종합 — (Q15) 데이터 형태 변화 순서도

```
[입력] video_path (예: "CLIP1_정상조립과정.mp4", 절대경로 문자열)
   │
   ├─ run.py --config config.yaml [--video 경로]  또는  run_all_clips.py 의 하드코딩 VIDEOS 리스트
   ▼
run_preflight(cfg)                                          [preflight.py]
   │   패키지/환경/config-종속 임포트/영상·weights_path·ffmpeg·GPU 존재 검증
   │   실패 시 Pipeline 생성 전에 sys.exit(1)
   ▼
Pipeline.run(video_path)                                    [orchestrator.py:86]
   │  meta = FrameMeta(video_id, path, fps=30.0(fallback), width=0, height=0, n_frames=0)
   │
   ├─[1/5] STT ───────────────────────────────────────────────────────────────
   │   video_path(파일 경로, str)
   │     → faster_whisper.WhisperModel.transcribe()  [내부에서 오디오 추출]
   │     → List[Utterance{start:float, end:float, raw_text:str, normalized_text:str(=raw_text 초기값)}]
   │     → Transcript{video_id, language, model, utterances}
   │     → transcripts/<video_id>.json 로 저장(raw 형태)
   │   Transcript → NormalizeRefiner.refine()
   │     → normalized_text 치환(en_normalization.json) + repeat_hallucination:bool 태깅
   │     → Transcript(정제본, raw_text는 원문 그대로 보존)
   │   → self.stt.unload()  [GPU 메모리 해제]
   │
   ├─[2/5] 프레임 추출(ffmpeg) ─────────────────────────────────────────────
   │   video_path(str) + fps(0.15 or 0.5, 길이기준 분기)
   │     → ffmpeg CLI subprocess (scale=long_side 480px, jpeg_q=5)
   │     → (frame_paths: List[str 경로], times: List[float 초])  ※ jpg 파일 = YOLO/VLM 공용
   │
   ├─[3/5] YOLO 검출 ───────────────────────────────────────────────────────
   │   frame_paths(jpg 리스트) → FrameRef 리스트(frame_idx, timestamp, image=None)
   │     → UltralyticsYOLODetector.detect()  [프레임별 개별 predict() 호출]
   │     → List[FrameDetections{timestamp, frame_idx, detections:List[Detection{cls,conf,bbox}]}]
   │     → flat_dets: List[Detection] (평탄화)
   │   (실패 시 try/except → flat_dets = [])
   │   → self.detector.unload()
   │
   ├─[4/5] VLM 관찰 ────────────────────────────────────────────────────────
   │   frame_paths(jpg) → PIL.Image 리스트(RGB) + flat_dets → injected_parts(부품명 리스트 or None)
   │     → build_video_observation_messages(injected_parts) → messages(system+user, video 포함)
   │     → processor.apply_chat_template(do_sample_frames=False) → model.generate()
   │     → raw: str(모델 원출력 텍스트, JSON 형태 기대)
   │     → _parse_observations(raw) → List[Dict](정상/부분복구/폴백 3단)
   │     → snap_to_grid(ts, times) 로 timestamp 보정 → sorted by timestamp
   │     → List[ActionDescription{timestamp:float, actor, action:str, objects:List[str], raw:str}]
   │   → output/vlm_observations/<video_id>.observations.json 저장(디버그용)
   │   → self.vlm.unload()
   │
   ├─[정렬] WindowAligner.align(actions, transcript, flat_dets) ─────────────
   │   ActionDescription 리스트 + Utterance 리스트 + Detection 리스트
   │     → ±4초 윈도우로 그룹핑, 미매칭 발화는 utterance_only 윈도우로 별도 수거
   │     → List[AlignedWindow{window_start, window_end, actions, utterances, detections, case}]
   │
   ├─[5/5] LLM 융합 ────────────────────────────────────────────────────────
   │   List[AlignedWindow] → _serialize() → List[Dict](case/시간/actions/utterances 순수 JSON)
   │     → build_fusion_messages(video_id, payload) → messages(system=FUSION_SYSTEM_PROMPT+LED표, user=payload JSON)
   │     → model.generate()/vllm.chat() → raw: str
   │     → _parse_and_validate(raw) → Pydantic 검증(TacitKnowledgeDocument)
   │       (검증 실패 시 최대 2회 재시도, 실패 컨텍스트를 대화에 append)
   │     → TacitKnowledgeDocument{schema_version, video_id, candidates:List[TacitKnowledgeCandidate]}
   │
   ├─[사후 교정] ──────────────────────────────────────────────────────────
   │   _finalize_metadata(doc, dur)      : id/scenario_id/source.* 를 코드가 강제로 채움(LLM 값 무시)
   │   enforce_evidence_grounding(...)   : evidence/timestamp를 VLM/STT 원본과 대조해 강제 정정
   │   cross_check(...)                  : 위반 의심 패턴을 경고 로그로만 출력
   │
   ▼
[출력] output/tacit_json/<video_id>.tacit.json
       {schema_version:"1.3", video_id, candidates:[{id, metadata{source{...}}, knowledge{situation, tacit_insight, reasoning, diagnostic_steps:[...]}}]}
```

**형태(Format/Shape) 변화 한 줄 요약**: `문자열(파일 경로)` → (STT 경로) `float 초 단위 세그먼트 리스트` / (영상 경로) `jpg 파일 리스트 + float 초 그리드` → `픽셀 bbox 검출 리스트` + `자연어 관찰 문장 리스트(VLM 원문 텍스트 → 파싱된 dict → Pydantic 모델)` → `시간 윈도우로 묶인 이종 데이터 그룹(dict)` → `LLM 원문 텍스트(JSON 문자열 기대)` → `Pydantic으로 검증된 계층적 JSON(스키마 v1.3)` → `사후 코드 교정을 거친 최종 디스크 JSON 파일`.

1. `orchestrator.py:50`: `# TODO(decision): 실제 영상 fps로 교체 — observe_video/motion 경로 쓸 때 위험` — `FrameMeta.fps`가 실제 영상에서 읽은 값이 아니라 `fps_override or 30.0` 하드코딩 폴백이라, 만약 `sampler`/`observe_video`(현재 미사용 경로)를 쓰게 되면 이 30.0 fps 가정이 실제와 달라 프레임↔초 변환이 틀어질 수 있음.
2. `vlm.params.input_mode`가 죽은 설정값(§1-1, 8번).
3. YOLO `detect()`가 프레임 배치 추론이 아니라 프레임별 순차 `predict()` 호출(§1-2).
4. `config.yaml`의 `vlm.max_new_tokens=1000`이 아직 "검증모드" 수치에 머물러 있고 스펙값(`4000`)으로 복구되지 않음(§5-1) — 이는 **evidence 태깅 신뢰도 이슈가 먼저 해결돼야 한다는 팀 의사결정** 때문(전처리_파이프라인_계획서.md §8 기준). (참고: `llm.max_new_tokens`는 500이 CLIP2에서 JSON 잘림 실패를 일으켜 2026-07-03에 스펙값 `2048`로 이미 복구됨 — VLM 쪽만 남은 문제.)
5. LLM의 `evidence`/`timestamp` 판단을 원천적으로 신뢰하지 않고 사후에 코드로 강제 정정하는 `enforce_evidence_grounding()`이 존재한다는 것 자체가, **로컬 sLLM(Qwen2.5) 단계에서 시간 정합성 추론이 아직 불안정하다**는 실측 결과의 방증.
6. `resources/videos_parts.example.json`이 이관 전 구버전 영상명(`master_S1_take3.mp4`)으로 남아있어 현재 CLIP1~4 실행 시 실질적으로 사용되지 않고 YOLO 자동 폴백에 의존.
