## 1. 배경 — 왜 재설계했나

구버전 STEP5는 LLM이 윈도우 여러 개를 클립당 후보 1건으로 뭉쳐서
4클립 합계 **후보 5건**(CLIP1은 1건에 스텝 31개)만 나왔다.
원인은 프롬프트 설계(후보 단위 정의 부재 + 병합 허용 조항 + scenario_title을
"클립 요약"으로 정의)였고, 이 상태로는 STEP6이 후보 단위로 거를 수가 없었다.

## 5. 핵심 발견 — 발화 계열 점수의 사각지대 (STEP6 기준 협의 안건)

STEP6 가중치는 발화 계열이 절반을 차지한다:
`reasoning_grounding 0.35 + utterance_signal 0.15 = 0.50`.
발화 계열이 0점이면 이론상 최대 0.5점(= step_grounding 0.3 + action_reason 0.2)
→ **accept(≥0.7)가 구조적으로 불가능**하고 reject 경계(0.4)에 깔린다.

reject된 GT(A2, A8)를 코드 수준으로 뜯어보면 발화 계열 0점의 실제 원인은
"발화가 없어서"가 아니라 두 가지 사각지대다 (A2 후보에는 발화가 2건 있었다):

1. **마커 사각지대 — '순서 지식'이 신호 0점.** `utterance_signal`은 발화 존재가
   아니라 "발화 스텝 중 신호 마커(인과 `때문에/하면/안 그러면/그래야`, 이탈
   `원래는/보통은/사실`, 주의 `꼭/절대/조심`, 부정 `하면 안/안 돼/안됩니다` —
   총 14개) 포함 비율"이다. A2의 발화 "전원 커넥터 **순서**가 있어요",
   "24핀 메인 **먼저** GPU 전원"은 전형적 절차 순서 지식인데 마커 목록에
   순서 계열(순서/먼저/~하고 나서/다음에)이 아예 없어 0/2 = 0.
   → 절차 순서형 암묵지 유형 전체가 감점되는 설계 공백.
2. **reasoning 미접지 — 절반은 STEP5(우리) 몫.** Gate C-1은 후보의
   `reasoning_source` 시각으로 전사본 발화를 가져와 판정하는데, STEP5의 LLM이
   A2의 reasoning을 발화 인용 없이 `model_inferred`(source 빈 배열) 일반론으로
   써서 근거 스니펫이 0건 → 0점. 바로 옆 스텝에 발화가 있었는데도 안 씀.

진짜 무발화(action_only 전용) 후보도 규칙상 rule_score 0에서 시작하며(코드 주석은
"LLM judge가 보정"이라 하나 실측에서 0 유지), 침묵 암묵지 A1·A2가 몰린 CLIP1은
3분 18초에 발화가 6건뿐인 발화 희박 클립 — 암묵지의 본진일수록 발화 계열
0.5 가중치에 불리하다.

제안(김보나님 협의): ① 마커 목록에 순서 계열 추가, ② action_only 후보용
별도 트랙(가중치 재배분) 또는 VLM 관찰 근거를 reasoning_grounding에 인정,
③ (우리 몫) STEP5 프롬프트에 "윈도우에 발화가 있으면 reasoning을 발화에
접지하고 reasoning_source를 채워라" 강화.

## 6. 분업 검증 — "STEP5는 다 건지고 STEP6이 거른다"

- reject 15건 중 GT 해당은 2건(위 구조 문제)뿐이고, 나머지 13건은
  "전원 버튼 누르기", "모니터 꺼짐 확인", "마우스 우클릭 메뉴 사용" 같은
  **평범한 절차 조각** — 걸러지는 게 맞는 후보들이다.
- hold 19건은 사람 검토 대기열로 남는다(GT 4건 포함 — 기준 조정 시 accept 승격 후보).
- 결론: 재현율(STEP5)/정밀도(STEP6) 분업이 의도대로 작동함을 처음으로 실증.

2. hold 19건 사람 검토 → accept 승격분 확정.
3. accept(+승격분)를 STEP7/8 RAG에 실데이터 재적재 → SIM_THRESHOLD 0.40 재보정
