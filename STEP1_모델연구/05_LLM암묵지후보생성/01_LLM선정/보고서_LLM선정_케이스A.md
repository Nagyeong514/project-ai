# 융합 LLM 선정 실험 보고서 — 케이스 A(행동+발화) 기준

작성: 2026-07-09 / 위치: `00_사전연구/03_LLM선정/` / 실행: 잡 2369·2373·2374 (n5, RTX 6000×2)
※ 본 보고서는 **케이스 A(행동+발화 융합 윈도우)만** 다룬다. 케이스 B(행동만)·C(발화만)를
포함한 전체 집계는 `summary.md` 참조.

## 1. 목적과 구도

시간 윈도우로 묶인 STT 발화와 VLM 행동 관찰을 입력으로 받아, "왜 이렇게 하는가"를
추론해 정형화된 암묵지 후보(JSON)를 생성하는 STEP5 융합 LLM을 선정하기 위한 비교
실험이다. 통제실험이 아니라 **실사용 비교**다 — 프롬프트는 STEP5 현행 융합 프롬프트
동결본, 입력은 실전 파이프라인 산출물(aligned_windows)을 그대로 사용했고, 게이트·재시도
없는 1-shot 생성으로 모델의 소성(素性)을 측정했다.

선정 기준: ① 크로스모달 융합 품질 ② 입력에 없는 사실을 지어내지 않음(충실도)
③ n5(Quadro RTX 6000 24GB, Turing)에서의 실용적 구동.

## 5. 모델별 출력 예시 (매핑 해제)

블라인드 채점지(`blind_eval.md`)의 출력 A/B/C는 `mapping_secret.json` 기준
**A = gemma3, B = llama31, C = qwen3vl**이다(매핑 해제는 채점지 생성·정량 집계
이후). 아래는 채점지에서 발췌한 케이스 A 실제 출력으로, §4 수치가 실제 어떤
출력 차이에서 나오는지 보여준다. **6윈도우 × 3모델의 생성 결과 전문**(입력 포함,
채점지에 없는 task/keywords/scenario_title 필드까지)은
**`모델별_생성전문_케이스A.md`** 참조.

### 5.1 같은 입력에 대한 세 모델 비교 — CLIP1_W01

입력(요약): 덮개를 당겨 여는 행동 2건 + RAM_slot 근처 녹색 PCB를 누르는 행동 1건,
발화 "케이스를 높여서 열고 마더보이드가 잘 보이도록 이렇게 세팅하면 됩니다".

**gemma3 (출력 A)**
> - situation: 정비공이 서버 케이스를 열고 RAM 모듈을 장착하기 위해 준비한다.
> - tacit_insight: RAM 모듈을 장착하기 전에 케이스를 열고 마더보이드가 잘 보이도록 설정해야 한다.
> - reasoning: 케이스를 열지 않으면 RAM을 장착할 수 없으며, 마더보이드가 보이지 않으면 정확한 위치를 찾기 어렵다.

→ 무난해 보이지만 이 윈도우 입력에 없는 "RAM 모듈 장착"을 앞질러 서술한다
(아래 5.2의 창작 경향과 같은 뿌리).

**llama31 (출력 B)**
> - situation: 정비공이 컴퓨터 케이스를 열고 있다.
> - tacit_insight: 케이스를 높여서 열면 마더보이드가 잘 보인다.
> - reasoning: 케이스를 높여서 열면 마더보이드가 잘 보인다.

→ 입력 밖으로 나가지 않아 접지는 높으나, reasoning이 tacit_insight의 동어반복이고
행동 관찰 3건을 사실상 사용하지 않는다(융합이 얕음).

**qwen3vl (출력 C)**
> - situation: 정비공이 서버 케이스 덮개를 당겨 열고, 열린 케이스 안의 마더보드를 확인하기 위해 덮개 가장자리를 잡고 고정한 후, 녹색 PCB 상단을 살짝 누름.
> - tacit_insight: 케이스를 열고 마더보드가 잘 보이도록 정렬한다.
> - reasoning: 정비공이 '케이스를 높여서 열고 마더보드가 잘 보이도록 이렇게 세팅하면 됩니다'라고 말함 — 마더보드 시야 확보 없이 작업하면 부품 위치 오류나 손상 위험이 있다.

→ 행동 3건과 발화를 모두 엮고, "발화 인용 → 안 하면 생기는 리스크" 구조로
근거를 세운다. 이 윈도우에서는 융합 밀도가 가장 높다.

**qwen3_14b** *(2026-07-11 추가 실행, run1 실제 출력)*
> - situation: 정비공이 서버 케이스의 덮개를 열며, 덮개를 고정한 뒤 마더보드가 잘 보이도록 케이스의 각도를 조정하고 있다.
> - tacit_insight: 덮개를 완전히 열고 고정한 뒤, 케이스의 각도를 조정하여 마더보드가 시야에 들어오도록 한다.
> - reasoning: 정비공이 '케이스를 높여서 열고 마더보이드가 잘 보이도록 이렇게 세팅하면 됩니다'라고 말함 — 마더보드를 확실하게 볼 수 있도록 케이스를 조정하지 않으면 작업 중 시야가 방해받을 수 있다.

→ qwen3vl과 같은 "발화 인용 → 리스크" 접지 구조에, 행동(덮개 고정·각도 조정)을
절차적으로 통합한다. llama31의 동어반복·gemma3의 앞지른 창작 문제가 없다 —
STEP5 실전 채택 모델이 이 벤치의 채택 기준(융합 밀도 + 인용 접지)을 사후적으로도
충족함을 보여주는 출력.

**gemma3_12b** *(2026-07-12 추가 실행, run1 실제 출력)*
> - situation: 정비공이 케이스 덮개를 열고 마더보드가 잘 보이도록 세팅하고 있다.
> - tacit_insight: 케이스를 열어 마더보드를 잘 보이도록 세팅하여 작업 공간을 확보한다.
> - reasoning: 정비공이 '케이스를 높여서 열고 마더보이드가 잘 보이도록 이렇게 세팅하면 됩니다'라고 말함 — 마더보드를 확인하기 위해 케이스를 열고 세팅해야 한다.

→ 4B가 이 자리에서 하던 "RAM 장착 앞지르기" 창작이 사라지고 발화 인용 접지를 지킨다.
다만 reasoning 후반이 insight의 재진술에 가까워(동어반복 경향) 융합 깊이는
qwen 계열보다 얕다 — 충실도 1위(89%)가 "창작을 안 한다"는 뜻이지 "융합이 깊다"는
뜻은 아닌, llama31과 같은 계열의 우위다.

### 5.2 모델별 특징 사례 (§4 플래그의 실체)

**gemma3 — 존재하지 않는 발화를 인용하는 환각** (CLIP1_W02): 입력 발화는
"케이스를 높여서…" 하나뿐인데,
> - tacit_insight: RAM 을 끼운 뒤 딸깍 소리로 래치가 잠겼는지 확인한다.
> - reasoning: 정비공이 '딸깍 소리가 나면 잠긴 거예요'라고 말함 — …

라며 **입력에 없는 발화를 따옴표로 지어내 인용**한다. 같은 "딸깍" 인사이트가
케이스 A 6윈도우 중 3개(CLIP1_W02·CLIP2_W01·CLIP3_W04)에 반복 삽입된다
(템플릿화). 충실도 최하위(44%)의 실체가 이것이다.

**llama31 — 접지 우위의 이면, 얕고 어색한 서술** (CLIP2_W02):
> - tacit_insight: GPU를 연결 상태를 확인해야 한다.
> - reasoning: 정비공이 '황색 4번에 백색 5번이면은 램 불량이네요'라고 말함 — 램 불량을 확인하기 전에 연결 상태를 확인해야 한다.

비문("GPU를 연결 상태를")이 나오고, 발화를 압축 복창하는 수준에 그친다.
CLIP2_W01에서는 "전원 버튼을 눌러서 컴퓨터가 켜지지 않으면 램 불량으로 오류가
발생할 수 있다"처럼 인과가 뒤틀린 서술도 있다. 즉 정량 충실도 1위(83%)는
"입력 밖으로 안 나간다"는 뜻이지 "행동과 발화를 잘 엮는다"는 뜻이 아니다.

**qwen3vl — 융합 밀도 최고, 대신 입력 어휘 밖 도메인 해석** (CLIP2_W01):
> - situation: 정비공이 컴퓨터 케이스 전원 버튼을 누르고, LED 진단 패턴을 확인한 뒤 케이스를 열어 GPU 클립을 조작하며 내부 점검을 시작한다.
> - tacit_insight: 전원 버튼을 누르고 LED 깜빡임 패턴을 통해 하드웨어 이상 여부를 진단한다.

입력 어디에도 "LED"라는 단어가 없다 — 발화 "황색 4번에 백색 5번"을 LED 진단
코드로 해석해 낸 것이다. 도메인적으로는 타당한 해석이지만 키워드 접지 휴리스틱에는
창작으로 잡힌다(run1 접지율 0.31 플래그). qwen3vl의 케이스 A 플래그 7건 상당수가
이런 "허위 인용"(gemma3형)이 아닌 "해석 확장"형이라, 정성 재확인에서 실제 환각과
정당한 일반화를 갈라 봐야 한다.

## 6. 정성 평가 (블라인드) — 진행 대기

세 모델의 출력을 모델명 제거 후 A/B/C로 익명화한 채점지 **`blind_eval.md`**
(15윈도우 전체 포함 — 케이스 A 6개는 문서 상단부)가 생성되어 있다. 채점 루브릭:
행동-발화 매칭 / 두괄식 / 어조·존대 / 자연스러움(각 1~5점). 모델 매핑은
`mapping_secret.json`에 분리 보관되어 채점지에는 노출되지 않는다.
**정성 채점은 본 실험 수행자(에이전트)가 하지 않는다** — 사람이 채점지를 별도
채점자(Claude 등)에게 넘겨 진행한다.

## 7. 잠정 정리 (최종 선정 아님)

합의된 판정 순서는 ① 충실도(관문) → ② 이행률+정성 매칭(승부처) → ③ latency/VRAM
(타이브레이커)이다. 케이스 A 정량만으로는:

- **llama31**: 충실도·접지율·속도 모두 1위 — 정량 잠정 우위.
- **qwen3vl**: 충실도 2위. STEP4 VLM과의 모델 단일화(운영 단순화)라는 정량 외 이점 보유.
- **gemma3**: 충실도 최하위(44%) + fp16 불가 전력. 경량 이점(VRAM 4.2GiB)에도 관문
  통과가 어려운 포지션.

**최종 선정은 블라인드 정성 채점(§6) 합산 후 확정한다.** 특히 이행률이 전원 100%로
동률이므로, 융합 품질(행동-발화 매칭)의 정성 점수가 사실상의 승부처가 된다 —
§5 예시에서 보듯 충실도 수치의 우열(llama31)과 융합 밀도의 우열(qwen3vl)이
갈리는 구도라, 이 두 축의 상대 비중이 정성 채점에서 결정된다.
