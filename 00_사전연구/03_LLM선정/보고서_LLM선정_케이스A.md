# 융합 LLM 선정 실험 보고서 — 케이스 A(행동+발화) 기준

작성: 2026-07-09 / 위치: `00_사전연구/03_LLM선정/` / 실행: 잡 2369·2373·2374 (n5, RTX 6000×2)
※ 본 보고서는 **케이스 A(행동+발화 융합 윈도우)만** 다룬다. 케이스 B(행동만)·C(발화만)를
포함한 전체 집계는 `summary.md` 참조.

## 1. 목적과 구도

시간 윈도우로 묶인 STT 발화와 VLM 행동 관찰을 입력으로 받아, "왜 이렇게 하는가"를
추론해 정형화된 암묵지 후보(JSON)를 생성하는 STEP5 융합 LLM을 선정하기 위한 비교
실험이다. 통제실험이 아니라 **실사용 비교**다 — 프롬프트는 STEP5 현행 융합 프롬프트
동결본, 입력은 실전 파이프라인 산출물(aligned_windows)을 그대로 사용했고, 게이트·재시도
없는 1-shot 생성으로 모델의 소성(素性)을 측정했다.

선정 기준: ① 크로스모달 융합 품질 ② 입력에 없는 사실을 지어내지 않음(충실도)
③ n5(Quadro RTX 6000 24GB, Turing)에서의 실용적 구동.

## 2. 비교 대상과 환경

| 키 | 모델 | 포지션 |
|---|---|---|
| qwen3vl | Qwen3-VL-8B-Instruct | 멀티모달(본 실험은 텍스트 입력만) — STEP4 VLM과 모델 단일화 구도 |
| llama31 | Meta-Llama-3.1-8B-Instruct (공개 미러) | 텍스트 전용 대조군 |
| gemma3 | gemma-3-4b-it (공개 미러) | 경량(4B) 검증 포지션 |

통제 변수(전 모델 동일, `bench_config.yaml`): 정밀도 **nf4**(bitsandbytes, compute fp16),
transformers 단일 스택(5.12.1 / torch 2.12.1+cu130), temperature 0.2 · top_p 1.0 ·
max_new_tokens 2048 · do_sample true, 동일 frozen 입력, 모델당 웜업 1회(집계 제외) +
본 실행 3회, 모델별 순차 실행(동시 실행 금지).

정밀도 경위: 1차 fp16 시도에서 gemma3가 생성 중 수치 오버플로(CUDA device-side
assert, 잡 2340 — bf16 전제 학습 모델의 fp16 한계)로 사망하여, "일부만 nf4 금지"
원칙에 따라 **세 모델 전부 nf4로 재실행**했다. fp16 결과(qwen3vl·llama31)는
`results/{model}/fp16/`에 보존.

## 3. 테스트 데이터 — 케이스 A 윈도우 6개

실전 4클립의 aligned_windows에서 행동·발화가 모두 존재하는 fusion 윈도우를 클립
라운드로빈으로 6개 선정(`windows_labels.json` 사전 확정, `frozen_windows.json`으로
3모델 공유). 모델당 6윈도우 × 3회 = **18레코드**.

| 윈도우 | 구간 | 행동/발화 수 |
|---|---|---|
| CLIP1_W01 | 0.0~18.0s | 3 / 1 |
| CLIP1_W02 | 14.0~32.0s | 3 / 1 |
| CLIP2_W01 | 12.0~32.0s | 4 / 1 |
| CLIP2_W02 | 26.0~42.0s | 3 / 1 |
| CLIP3_W04 | 46.0~62.0s | 4 / 1 |
| CLIP4_W05 | 69.0~89.0s | 7 / 2 |

## 4. 정량 결과 (케이스 A, 18레코드/모델)

| 지표 | qwen3vl (8B) | **llama31 (8B)** | gemma3 (4B) |
|---|---|---|---|
| 평균 latency | 61.5±3.6s | **33.3±3.8s** | 52.1±5.0s |
| 생성 속도 | 4.8 tok/s | **6.0 tok/s** | 4.6 tok/s |
| VRAM peak (nf4) | 8.4 GiB | 7.4 GiB | **4.2 GiB** |
| 지시 이행률 (파싱+스키마+규칙) | **100% (18/18)** | **100% (18/18)** | **100% (18/18)** |
| 사실적 충실도 (무플래그 비율) | 61% (11/18) | **83% (15/18)** | 44% (8/18) |
| 키워드 접지율 평균 | 0.51 | **0.60** | 0.45 |
| 환각 플래그 | 키워드접지<0.5 ×7 | 키워드접지<0.5 ×3 | 키워드접지<0.5 ×10 |

- **이행률은 세 모델 모두 만점** — JSON 파싱·FusionDraft 스키마·한국어·금지필드 위반이
  단 1건도 없었다. 형식 준수는 변별점이 아니다.
- **충실도에서 llama31이 뚜렷하게 우세**(83% vs 61% vs 44%). 플래그는 전부 키워드 접지
  미달(출력 명사의 절반 이상이 입력 텍스트에 없음 = 창작 의심)이며, 케이스 A에서는
  시각 환각(존재하지 않는 timestamp 인용)과 케이스 위반이 **세 모델 모두 0건**이었다.
- 충실도 휴리스틱의 한계: 키워드 접지는 형태소 명사 겹침 기반 근사치로, 정당한
  일반화 표현도 플래그될 수 있다. 플래그 상세 목록(`summary.md` 하단)이 정성 재확인
  대상이며, 이 수치는 스크리닝용이다.
- 속도: llama31이 qwen3vl 대비 약 1.8배 빠르다. VRAM은 셋 다 단일 카드에 여유.

## 5. 정성 평가 (블라인드) — 진행 대기

세 모델의 출력을 모델명 제거 후 A/B/C로 익명화한 채점지 **`blind_eval.md`**
(15윈도우 전체 포함 — 케이스 A 6개는 문서 상단부)가 생성되어 있다. 채점 루브릭:
행동-발화 매칭 / 두괄식 / 어조·존대 / 자연스러움(각 1~5점). 모델 매핑은
`mapping_secret.json`에 분리 보관되어 채점지에는 노출되지 않는다.
**정성 채점은 본 실험 수행자(에이전트)가 하지 않는다** — 사람이 채점지를 별도
채점자(Claude 등)에게 넘겨 진행한다.

## 6. 잠정 정리 (최종 선정 아님)

합의된 판정 순서는 ① 충실도(관문) → ② 이행률+정성 매칭(승부처) → ③ latency/VRAM
(타이브레이커)이다. 케이스 A 정량만으로는:

- **llama31**: 충실도·접지율·속도 모두 1위 — 정량 잠정 우위.
- **qwen3vl**: 충실도 2위. STEP4 VLM과의 모델 단일화(운영 단순화)라는 정량 외 이점 보유.
- **gemma3**: 충실도 최하위(44%) + fp16 불가 전력. 경량 이점(VRAM 4.2GiB)에도 관문
  통과가 어려운 포지션.

**최종 선정은 블라인드 정성 채점(§5) 합산 후 확정한다.** 특히 이행률이 전원 100%로
동률이므로, 융합 품질(행동-발화 매칭)의 정성 점수가 사실상의 승부처가 된다.
