# LLM 모델링 평가 보고서 — Qwen3-VL-8B-Instruct / Llama-3.1-8B / Gemma-3-4B

- 실행: 2026-07-07, n5(Quadro RTX 6000) srun 잡, `run_benchmark_n5.sh` → `evaluate_llm.py`
- 구도: **Qwen3-VL-8B-Instruct는 STEP4 비디오 관찰(VLM)에 쓰는 모델과 동일** — 파이프라인에
  이미 올라가는 모델이 STEP8 RAG 답변 LLM까지 겸할 수 있는지를 함께 본다.
- 데이터: `STEP7_DB/gold_records` 9건 × 시나리오 A(정상)/B(노이즈 주입) + C(무관 질의) 1건 = 모델당 19케이스, 총 57케이스 (API 실패 0, 빈 답변 0)
- 양자화: **셋 다 Ollama Q4_K_M (GGUF 4bit)** — 태그 메타데이터로 실측 확인.
  ★ STEP4는 transformers+**nf4** 로딩이므로 같은 4bit여도 양자화 방식이 다름 — 이 결과를
  STEP4 인스턴스에 그대로 이식할 때는 재확인 필요.
- 원본 답변 전문: `llm_benchmark_results.json`

## 0. 실행 중 발견한 태그 함정 (재발 방지용 기록)

Ollama 기본 태그 `qwen3-vl:8b`는 Instruct가 아니라 **Thinking 변형**이다(digest
901cae ≠ instruct 0533d7). 이걸 모르고 돌린 1차 실행에서 호출당 30~60초(평균 39.5초),
19건 중 6건은 60초 내내 thinking만 하다 **빈 본문**을 반환했고, API에 `think:false`를
보내도 잡히지 않았다. **STEP4와 같은 모델을 쓰려면 반드시 `qwen3-vl:8b-instruct`를 명시**할
것. (오염 실행 기록: `llm_benchmark_results_v2_thinking_bug.json`)


## 2. 사실적 충실도 재채점 (LLM judge, 답변 전문 대조)

채점 기준: ① 컨텍스트에 없는 내용 창작(환각) ② 핵심 누락/왜곡 ③ 시나리오 B에서
[무관한 절차] 노이즈를 답변 절차에 편입 ④ 시나리오 C 거부 이행.

| | Qwen3-VL-8B-Instruct | Llama-3.1-8B | Gemma-3-4B |
|---|---|---|---|
| 재채점 충실도 | **47.4% (9/19)** | 42.1% (8/19) | **47.4% (9/19)** |
| 휴리스틱 근사 | 63.2% | 57.9% | 57.9% |
| 시나리오 A (9건) | 5 pass | 6 pass | 6 pass |
| 시나리오 B (9건) | 3 pass | 1 pass | 2 pass |
| 시나리오 C (1건) | pass | pass | pass |

**세 모델 모두 충실도 50% 미만** — 어느 모델이든 생성 답변을 그대로 현장에 읽어주기엔
부족하고, 검색 차단·출처 후처리 같은 시스템 측 방어(§4)가 전제되어야 한다. 키워드
휴리스틱이 세 모델 모두를 과대평가한 이유는 A시나리오의 "그럴듯한 창작"(키워드는 겹치는데
내용은 지어냄)을 원리적으로 못 잡기 때문이다.

### 휴리스틱 판정과 달라진 항목 (14건)

**Qwen3-VL-8B-Instruct (휴리스틱 12 → 재채점 9)**
1. `A-BIOS확인` PASS→FAIL: 답변이 "BIOS 설정에서는 메모리"에서 **중간에 잘림**(1.32초,
   조기 종료). 키워드 '메모리'가 있어 휴리스틱은 통과시켰지만 내용 자체가 없음.
2. `A-래치확인` PASS→FAIL: 잠금 '확인' 절차를 "래치를 당겨보며... **잠금이 해제된
   것입니다**"로 서술 — 체결 확인을 해제 절차로 뒤집는 의미 왜곡.
3. `B-래치확인` PASS→FAIL: 같은 왜곡 반복("래치를 당겨서 물리적으로 **잠금 해제**하고").
4. `A-LED판독` PASS→FAIL: "전원 끄고 10초 대기", "쿨러 상태와 히트싱크 연결, 전원공급
   장치를 점검" 등 컨텍스트에 없는 절차 대량 창작.
5. `A-단자세척` PASS→FAIL: "스프레이 세정제 또는 **스포츠브러시**" — 지어낸 도구 예시에
   비실재 용어까지 섞임.
6. `B-채널식별` FAIL→PASS: 유출 단어(구성/반드시 등)가 전부 일반어 오탐. 핵심 답 온전,
   노이즈 절차 미편입.
7. `C-무관질의` FAIL→PASS: "죄송하지만, 현재 제가 보유한 정보는 없습니다" — 정상 거부인데
   거부 마커 정규식이 못 잡음("정보는 없" ≠ "정보가 없").

**Llama-3.1-8B (휴리스틱 11 → 재채점 8)**
8. `A-채널식별` PASS→FAIL: "메모리 채널을 식별하는 **방법은 없습니다**. 공식 매뉴얼이나
   manufactruer의 웹 사이트에서 확인" — 컨텍스트(색상·라벨로 식별)를 정면 부정.
9. `A-LED판독` PASS→FAIL: "단지점: 전원 문제 / 점멸: CPU 오류 / 정전: 배터리 문제" —
   존재하지 않는 점멸 패턴 진단표를 통째로 창작.
10. `A-촉각커넥터` PASS→FAIL: "**장비가 켜진 상태에서** 커넥터를 확인합니다" — 컨텍스트에
    없는 통전 상태 작업 지시(안전 문제 소지).

**Gemma-3-4B (휴리스틱 11 → 재채점 9)**
11. `A-부팅전점검` PASS→FAIL ★치명: "초보자는 이 단계를 건너뛰고 임의 슬롯에 장치를
    꽂습니다"를 **절차 2번 단계로** 제시 — 컨텍스트의 실수 서술을 지시로 변환.
12. `A-채널식별` PASS→FAIL: 6채널 전용 장비 컨텍스트에서 "보통 **듀얼 채널** 구성이
    가능하며" + 슬롯 색상 확인 절차에 "워크스테이션을 켜고 전원 버튼을 누릅니다" 창작.
13. `A-RDIMM탈거` PASS→FAIL: 양쪽 래치 동시 누름(탈거 시 규칙)을 탈거 단계에서 빼고
    "재장착할 때"로 잘못 귀속 — 안전 규칙의 적용 시점 왜곡.
14. `B-단자세척` FAIL→PASS: 유출 단어가 '반드시' 하나(일반어 오탐). 노이즈 무시하고 핵심만
    답한 모범 사례.

## 3. 정성 평가 (음성 가독성/어조/포맷)

**Qwen3-VL-8B-Instruct** — 두괄식·존댓말은 대체로 일관, 문장도 간결. 감점: ① 답변 1건이
문장 중간에서 잘림 ② 비실재/어색한 어휘가 간헐 등장("래치를 잡아 **펑크처럼** 밀어내세요",
"스포츠브러시", "단단히 잠그였는지") — TTS로 읽히면 그대로 노출 ③ 출처 영상ID 누락
8/19건(위 참조) ④ 래치 의미 왜곡 2건(안전 절차라 치명).

**Llama-3.1-8B** — 가장 빠름(2.46초). 그러나 반말·명령조 혼입("부팅 성공이 아니다.",
"LED 점멸 패턴을 읽어내라."), 한자 노출("단자가**乾燥**되면" — TTS 발음 불가), 영어
오타("manufactruer"), 자신 없는 종결("정비가 제대로 된 것 같아요"), 타임스탬프 변조
3건. 지시 이행률 100%는 마크다운·출처 '형식'만 본 수치.

**Gemma-3-4B** — 지시 이행 100%, C 거부도 성공("죄송하지만 현재 암묵지에 점심 메뉴에
대한 정보가 없습니다"). 그러나 매 답변 인사·호칭 표류("안녕하세요, 신입 작업자님!" ↔
"네, 고객님.")로 두괄식 약화, **컨텍스트의 실수 서술을 절차로 바꾸는 의미 반전 결함**
2건(안전 문제), 출처에 backslash escape 노출 1건(`master\_boot\_clip2.mp4`).

## 4. 결론

세 모델 중에서는 **Qwen3-VL-8B-Instruct 채택을 권고**한다. 근거: 충실도 공동 1위(47.4%),
시나리오 B 노이즈 방어 최다(3/9), C 거부 정상, 어조 일관성 최고, 그리고 STEP4 VLM과
모델을 단일화해 VRAM(7.0 GiB)과 운영 부담을 줄일 수 있다. Llama는 속도(2.46초) 외에는
환각 창작·컨텍스트 부정·타임스탬프 변조로 부적합, Gemma는 포맷 이행 100%가 무색하게
안전 절차 의미 반전이 반복되어 부적합.

단, **어느 모델도 충실도 50%를 못 넘으므로 모델 선택만으로는 부족**하다. 서비스에는
다음 시스템 측 방어를 전제로 한다:
1. STEP7 검색 SIM_THRESHOLD로 무관 컨텍스트 유입 자체를 차단 (프롬프트의 "[무관한 절차]
   무시" 지시는 세 모델 모두 안 지킴)
2. 출처 줄은 LLM 생성에 맡기지 말고 검색 메타데이터로 후처리 생성 (영상ID 누락 8/19건
   대응)
3. 래치/탈거 등 안전 관련 답변은 재검증 장치 필요 (잠금 확인→해제 의미 왜곡 2건 대응)
4. Ollama 태그는 반드시 `qwen3-vl:8b-instruct` 명시 (§0 함정)
