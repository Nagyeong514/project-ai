# 감사 1. LLM이 자유 창작 가능한 필드 전수와 검증 매트릭스

LLM이 쓸 수 있는 필드는 `DraftCandidate`/`DraftKnowledge`(`tacit_schema.py:217-239`)가 전부다. 필드별 검증(코드 근거 포함):

| 필드 | 문자열 접지 검증 | 그 외 검증 | 판정 |
|---|---|---|---|
| `knowledge.reasoning` | **유일하게 있음** — 단 `reasoning_origin=="utterance"`일 때만(`llm_fusion.py:254-255`에서 model_inferred는 `continue`로 스킵) | 재시도 피드백 → 소진 시 origin 강제 교정(`:349-359`) | 조건부 검증 |
| `knowledge.situation` | **없음** — `_ungrounded_utterance_claims`는 `c.knowledge.reasoning`만 읽는다(`llm_fusion.py:260-262`). situation을 읽는 검증 코드는 파일 전체에 없음 | 스키마 존재 여부만(필수 필드) | **자유 창작** |
| `knowledge.tacit_insight` | **없음** (동일 — 검증 코드 부재) | 스키마 존재 여부만 | **자유 창작** |
| `metadata.task` / `keywords` / `scenario_title` | **없음** — llm_fusion.py·step5_runner.py 어디에도 이 필드를 대조하는 코드 없음 | 없음(Optional, 비어도 통과) | **자유 창작** |
| `knowledge.conflict` / `conflict_detail` | 없음 | `cross_check`가 "conflict=true인데 detail 없음"만 경고(`tacit_schema.py:189-190`) — **false 오태깅(충돌 은폐)은 어떤 코드도 안 봄** | **자유 창작** |
| `knowledge.reasoning_origin` | 접지 게이트 + 강제 교정 3곳(발화 0건 `:557-560` / 소진 시 `:355-359` / Pass 2 `:750-753`) | — | 강검증(utterance 방향만) |
| `window_ids` | — | 귀속 게이트 3종(`:447-484`) — 형식만, 의미는 무검증 | 형식 강검증 |

**참고 — 나머지 콘텐츠 게이트 2종은 1.4 구조상 사실상 사문(死文)이다**:
- 발화 커버리지(`_missing_utterances`, `:277-292`): source_utterance는 LLM이 아니라 `_rebuild_from_draft`가 윈도우 발화 전량에서 채우고(`:551-554`), 귀속 게이트가 전 윈도우 귀속을 보장하므로 **비환각 발화는 구조적으로 전부 출력에 포함**된다 — 이 게이트는 1.4에서 실패할 수 없다(실측: CLIP4 미반영 0건).
- `cross_check` 둔갑·지어냄 탐지(`tacit_schema.py:170-183`): 대조 대상인 source_utterance 자체를 코드가 채우므로 1.4에선 회귀 방어용이다(잡 2437 전 클립 경고 0건).

즉 **"발화를 지어내는" 구멍은 1.4가 코드로 막았지만, "발화·관찰에 없는 서술을 짓는" 구멍은 reasoning(utterance 태깅 시) 한 곳만 부분적으로 막혀 있다.**

# 감사 2. model_inferred reasoning은 어떤 검증을 받는가 — **안 받는다**

- 접지 게이트 진입 조건: `if c.knowledge.reasoning_origin != ReasoningOrigin.UTTERANCE: continue` (`llm_fusion.py:254-255`). **model_inferred 후보의 reasoning은 게이트 로직에 아예 진입하지 않는다.**
- 이후 경로에도 내용 검증 없음: `_rebuild_from_draft`는 서술을 그대로 복사(`:581-584`), cross_check는 reasoning을 안 봄, 러너는 저장만.
- 따라서 **`reasoning_origin="model_inferred"`라고 선언하는 순간 상식 서술이 무제한 허용**된다. 설계 의도이기도 하다 — 스키마 주석 "MODEL_INFERRED: LLM 일반지식으로 채움"(`tacit_schema.py:44-45`), 게이트의 목적은 '상식 차단'이 아니라 '상식을 발화 근거로 위장하는 것 차단'(`llm_fusion_prompt.py:16` "추론을 발화 근거인 척 위장 절대 금지")이다. 감사 관점의 함의: **tacit.json의 model_inferred reasoning 10/24건은 태깅만 정직할 뿐, 내용의 사실성은 아무도 검증한 적 없다**(하류 STEP6 채점이 유일한 방어선).

# 감사 4. 실산출물 24건 전수 대조 — 혼입 사례 목록

표기: **[후보 id / origin]** → 필드 원문 ↔ 대조한 입력 원문. (24건 전건에서 자동 플래그가 나왔고, 아래는 그중 개념·인과 수준의 사례 전부 — 기능어·표현 차이는 제외.)

### 사례 1 — 시스템 프롬프트(LED 코드표) 어휘 유출 + 충돌 미신고 [tk_CLIP2_001 / utterance] ★최중요

```
keywords: ["전원 버튼", "LED", "진단", "메모리", "프로세서"]
tacit_insight: "전원 버튼 LED의 깜빡임 패턴을 통해 하드웨어 문제를 추론한다."
↔ W01 발화 전문: "황색 4번에 백색 5번이면은 램 불량이네요"
↔ W01 관찰 전문: "…흰색 LED가 3번 깜빡인다" 외 3건 (메모리/프로세서/진단/하드웨어 없음)
```

- **'메모리'·'프로세서'·'진단'은 CLIP2 user 프롬프트(발화+관찰 payload) 내 0회, 시스템 프롬프트의 LED 코드표에만 존재**(실측: user 0회 / system 각 1·2·2회). 즉 이 keywords는 명장의 말이 아니라 **우리가 프롬프트에 넣어준 진단표의 행("황색 1회 + 백색 3회 : 메모리/프로세서 문제")에서 유출**된 것이다. 발화의 패턴(황4+백5)은 표에 없는 패턴인데도 표의 어휘가 검색 키워드로 박제됐다. '하드웨어'는 프롬프트 어디에도 없는 순수 모델 어휘.
- 동시에 **conflict=false**: 관찰(흰색 3회) vs 발화(황색 4회+백색 5회)는 스키마 주석이 conflict의 대표 예시로 든 바로 그 유형("LED 횟수 불일치", `tacit_schema.py:98`)인데 미신고됐다 — 절대 규칙 5가 당부만으로 안 지켜진 실증.

### 사례 2 — model_inferred 순수 상식 인과 [tk_CLIP2_003 / model_inferred]

```
reasoning: "GPU가 제대로 고정되지 않으면 작동 중에 손상이나 불안정한 작동이 발생할 수 있다
           — 고정 상태를 점검하는 것은 안정적인 작동을 보장하기 위한 필수 단계이다."
↔ 멤버 윈도우(W03·W04) 발화: 0건 / 관찰: GPU를 흔들고 당기는 동작 서술뿐
```

'손상', '불안정', '안정적인 작동 보장', '필수 단계' 전부 입력에 없음(클립 전체에도 없음). 감사 2대로 **검증 0회로 통과** — 정직 태깅(model_inferred)이라 설계상 합법이지만, 이 문장은 명장의 지식이 아니라 Qwen3의 지식이다.

### 사례 3 — utterance 태깅인데 인용 밖에 상식 확장 [tk_CLIP2_004 / utterance]

```
reasoning: "정비공이 '안그러면은 슬롯이 파손될 수가 있습니다'라고 말함 — 래치를 동시에 누르지
           않으면 RAM 슬롯이 손상될 수 있으며, 이는 장비의 안정성과 수명에 영향을 줄 수 있다."
↔ 발화 원문: "램을 뺄때는 양쪽을 동시에 눌러 줘야 합니다" / "안그러면은 슬롯이 파손될 수가 있습니다"
```

명장은 '파손'까지만 말했다. **"장비의 안정성과 수명에 영향"은 상식 덧붙임**인데, 접지 게이트는 인용문('안그러면은 슬롯이 파손될…')이 발화와 매칭되는 순간 후보 전체를 통과시킨다(`llm_fusion.py:262-266` — 첫 매칭에서 `grounded=True; break`). utterance 태깅이 "이 reasoning 전체가 발화 근거"라는 보증처럼 하류(STEP6·STEP7 검색)에 읽히는 것과 달리, 실제 보증 범위는 인용문 한 조각이다.

### 사례 4 — 접지 게이트의 '무관한 발화 인용' 통과 + 상식 인과 [tk_CLIP1_002 / utterance]

```
reasoning: "정비공이 '케이스를 눕혀서 열고 마더보드가 잘 보이도록 이렇게 세팅하면 됩니다'라고 말함
           — 고정핀을 누르지 않으면 RAM이 제대로 뽑히지 않을 수 있다."
↔ W02 발화 전문(±4초 겹침으로 W01의 세팅 발화가 흘러든 것): 위 인용 그대로 1건뿐
↔ W02 관찰: "RAM을 RAM_slot에서 완전히 뽑아내면서 손가락으로 고정핀을 누르는 듯한 움직임…"
```

인용된 발화는 **RAM 제거와 무관한 케이스 세팅 발화**지만 '그 윈도우에 실존하는 발화'라 게이트를 통과했고(게이트는 인용의 실존만 보지 주제 관련성은 안 본다), 대시(—) 뒤의 인과("고정핀을 누르지 않으면 제대로 뽑히지 않을 수 있다")는 발화 어디에도 없는 상식이다. '고정핀' 어휘 자체는 VLM 관찰에서 온 것(창작 아님) — 창작은 인과 연결이다.

### 사례 5 — 침묵 윈도우 상식 서술(프롬프트가 공식 요구) [tk_CLIP1_008 / model_inferred]

```
reasoning: "케이블을 정리하지 않으면 케이스 내부에서 열기와 전기 문제 발생 가능성이 있다."
↔ W09 발화: 0건 / 관찰: 케이블 정리·GPU 고정 동작 서술뿐 ('열', '전기 문제' 없음)
```

같은 유형: tk_CLIP1_007("전원 문제나 부품 결함"), tk_CLIP1_009("부품 결함"), tk_CLIP4_001/004/005("작업을 시작/수행할 수 없다", "문제를 진단할 수 없다"). 침묵 암묵지 조항(`llm_fusion_prompt.py:112-119`)이 "무엇을 **왜** 확인하는지 적어라"고 요구하므로 이 경로는 버그가 아니라 **설계된 상식 유입구**다.

### 사례 6 — 발화 1건의 과잉 일반화 [tk_CLIP3_재부팅시도 전까지_001 / model_inferred]

```
tacit_insight: "작업 시작을 명시적으로 알리는 것이 작업 흐름을 관리하는 방법이다."
reasoning: "작업 시작을 알리지 않으면 작업 진행 상황을 파악하기 어려울 수 있다."
↔ W01 발화 전문: "시작합니다."
```

두 글자짜리 발화에서 '작업 흐름 관리 방법론'이 생성됐다. tacit_insight는 검증 필드가 아니므로(감사 1) 그대로 저장됐다.

### 사례 7 — Pass 2 병합 서술의 새 어휘 [tk_CLIP3_재부팅시도 전까지_003 / utterance, 병합 그룹 c03~c06]

```
병합 tacit_insight: "RAM 삽입 전 청결과 점검을 하고, 삽입 후 전원 흐름을 확인하는 것이
                    안정적인 작동을 보장하는 방법이다."
↔ 멤버 4건(pass1)의 서술 합집합: '안정적인/작동을/보장하는/방법이다' 없음 (실측 대조)
```

Pass 2 프롬프트의 "멤버 서술에 있는 내용만 재료로 쓴다" 조항은 당부뿐이고, `_check_grouping`은 서술을 대조하지 않는다. 병합 재작성 1회가 곧 상식 어구("안정적인 작동 보장") 유입 1회였다.

### 사례 8 — (부차) 타 윈도우 발화의 개념 이동 [tk_CLIP3_재부팅시도 전까지_002 / model_inferred]

```
reasoning: "오염이 남아 있다면 전기 접촉이 불량해질 수 있다."
↔ W02(멤버 윈도우) 발화: 0건 — 그런데 '접촉 불량'은 같은 클립 W05 발화
  "산화막이 접촉 불량을 만들 수가 있습니다."에 실존
```

창작이 아니라 **명장이 실제로 말한 개념이 다른 시각의 침묵 후보로 이동**한 것(프롬프트가 클립 전체 윈도우를 한 번에 주기 때문에 가능). 지연 발화 습관을 감안하면 오히려 올바른 추론이지만, model_inferred로 태깅돼 있어 이 연결의 발화 근거가 메타데이터상 소실된다 — "말한 것"이 "모델 상식"으로 강등되는 역방향 왜곡.
