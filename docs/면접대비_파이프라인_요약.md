# STEP3 전처리 파이프라인 — 면접 대비 핵심 요약 (A4 3장 분량)

> 상세 전체 버전: `docs/면접대비_파이프라인_심층분석.md` (코드 인용 전체). 이 문서는 그 요약본.

## 1. 한 줄 정의

스마트글래스로 찍은 PC 수리 영상 1개를 입력받아, **STT(음성)** 와 **VLM(영상 관찰)** 을 독립적으로 처리한 뒤 **LLM 융합**으로 하나의 "암묵지 후보 JSON"을 만드는 5단계 순차 파이프라인(`tacit_pipeline/orchestrator.py`).

```
영상 ─┬─[음성] STT(Whisper) → 정제(정규화+반복태깅)
      └─[영상] ffmpeg 프레임추출 → YOLO 검출(위치) → VLM 관찰(observations)
                    └───────────┬───────────┘
                     ±4초 윈도우 정렬
                          ↓
              LLM 융합(Qwen2.5) → 암묵지 후보 JSON(v1.3)
```

**설계 철학 3줄**: ① VLM은 "눈" — 관찰만, 해석은 금지 ② 모든 중간 데이터는 초(float) 단위로 통일 ③ 이 파이프라인은 "후보 생성"까지만, 진위 판별은 다음 단계.

## 2. 처리 단위 & 핵심 스위치

- **처리 단위**: 영상 1개 = `Pipeline.run()` 1회 호출. 멀티스레딩/배치 없음. 여러 클립은 `run_all_clips.py`가 **모델 재로딩만 방지**하며 순차 for-loop 처리. YOLO도 프레임별 개별 `predict()`(배치 아님).
- **모델 교체 방식**: `config.yaml`의 `impl` 문자열 → `registry.py`의 딕셔너리 매핑 → 어댑터 클래스 생성. 새 모델 추가 시 기존 코드 무수정이 원칙.

| 스위치 | 기본값 | 효과 |
|---|---|---|
| `detector.impl` | `yolo_ultralytics` | `noop`이면 YOLO 자체를 안 돌림(과거 8GB VRAM 절약용, 지금은 불필요) |
| `vlm.params.part_injection` | `True` | 부품명을 프롬프트에 `[고정 사실]`로 주입할지. `videos_map_path`가 없으면 YOLO 검출로 자동 대체 |
| `vlm.params.input_mode` | `native_video` | ⚠️ 죽은 설정값 — 코드에 분기 없음, 항상 `observe_frames()` 직접 호출 |
| `stt.params.vad_filter` | `True` | faster-whisper 내장 VAD. 오디오는 안 자르고 무음만 스킵(과거엔 Silero로 잘라 붙이다 타임스탬프 어긋남 확인 후 전환) |
| `llm.backend` | `hf_transformers` | 원래 `vllm`이었으나 Turing GPU + sudo 없음 → JIT 컴파일 불가로 포기, VLM과 동일 방식(NF4)으로 전환 |
| `detector.params.strict_names` | `False` | YOLO 클래스명 불일치 시 예외(`True`) vs 경고만(`False`) |
| `llm.params.max_retries` | `2` | 스키마 검증 실패 시 재시도 횟수(최대 3회 시도) |

## 3. 프롬프트 엔지니어링 핵심

**VLM 시스템 프롬프트 요지** (`prompts/vlm_observation.py`): "당신은 눈이다, 관찰만 한다." 6대 절대 규칙 — ① 해석·진단·묶기 금지 ② 추상동사(확인/점검) 금지 → 구체 동작만 ③ 손가락 단위 분리 서술 ④ 측정값 추정 금지(단, 셀 수 있는 건 허용) ⑤ LED는 색+횟수만, 의미 해석 금지 ⑥ 안 보이는 건 적지 않기. Few-shot 3건으로 형식 강제.

**STT는 프롬프트가 아니라 디코딩 파라미터로 통제**: `condition_on_previous_text=False`(환각 억제) + VAD + 사후 정규화(`en_normalization.json`, 예: 마더보이드→motherboard) + 환각 상투구 denylist("다음 영상에서 만나요" 등 7종, 삭제 안 하고 태깅만).

**VLM·STT 결합 지점**: `WindowAligner.align()`이 행동을 앵커로 ±4초 이내 발화를 묶고(`case`: fusion/action_only/utterance_only), 이 결과를 JSON 문자열로 통째로 LLM user 프롬프트에 삽입. **API 레벨 결합이 아니라 프롬프트 텍스트 결합.**

**LLM 융합 프롬프트 핵심 규칙**: 할루시네이션 금지(입력에 없는 사실 생성 금지, 묶기/분류만 허용) + `reasoning_origin`(utterance/model_inferred) 정직 태깅 + 발화·행동 **누락 절대 금지**(둘 다 최대한 보존, 압축보다 보존 우선) + 본 것과 들은 것이 충돌하면 판단하지 말고 `conflict=true`로 둘 다 보존 + LED 진단 코드표는 **여기(LLM)에만** 있음(VLM은 모름).

## 4. JSON 포맷 강제 전략 (JSON mode 없이)

로컬 모델이라 API의 JSONмode를 못 써서, **프롬프트 강제 + 후처리 파싱**으로 대체:
1. 시스템/유저 프롬프트에 "이 JSON만 출력, 배열 밖 텍스트 금지" 반복 명시 + few-shot 스켈레톤 노출
2. 생성 파라미터(`repetition_penalty=1.2`, `do_sample=False`)로 반복/발산 억제
3. **메타데이터는 LLM에 안 맡김** — `id`/`scenario_id`/`source.*`는 오케스트레이터가 자동으로 덮어씀(과거 LLM이 `"..."` placeholder를 그대로 뱉은 사고 때문)

**파싱/검증/재시도**:
- VLM: 정상 JSON 파싱 → 실패 시 brace-매칭으로 완성된 관찰 객체만 부분 복구(`_salvage_observations`) → 그래도 실패면 원문 텍스트를 관찰 1건으로 폴백. **절대 완전 실패하지 않음.**
- LLM: `json.loads()` → Pydantic `model_validate()`. 실패 시 실패한 응답+에러 메시지를 대화에 추가해 최대 2회 재시도. 3회 다 실패하면 `RuntimeError`.
- **사후 코드 교정(핵심)**: `enforce_evidence_grounding()` — LLM이 매긴 timestamp/evidence를 VLM·STT 원본과 대조해 **코드가 강제로 고침**. 실제 사고: LLM이 t=2초 행동 관찰의 timestamp를 엉뚱한 1:01 발화 시각으로 바꿔치기한 걸 발견 → 이후 원본과 4초 이상 차이나면 자동으로 `action_only`로 강등하는 로직 추가.

## 5. 데이터 변형 핵심 수치

| 항목 | 값 | 근거 |
|---|---|---|
| 프레임 리사이즈 | 긴 변 480px | ffmpeg scale 필터 |
| 프레임 fps | 짧은 영상 0.5 / 120초 이상 0.15 | 긴 영상 OOM·중복 프레임 방지 |
| VLM `max_pixels` | 192×192(36864) | 128px는 부품 오인 확인, 상향 |
| 정렬 윈도우 | ±4.0초 | "행동·발화는 동시에 안 일어난다" 전제 |
| YOLO `conf`/`imgsz` | 0.25 / 640 | 표준 |
| Whisper VAD threshold | 0.5 | Silero 기본값, 0.2로 낮춰도 효과 무의미 실측 |

**타임스탬프 원칙**: 프레임 timestamp는 모델이 아니라 `i/fps` 그리드에서 코드가 부여 → VLM이 뱉은 시각은 `snap_to_grid()`로 가장 가까운 그리드값으로 강제 보정(모델 추정 시각을 안 믿음).

## 6. 하이퍼파라미터 스냅샷 (운영 config 기준)

| 모델 | 핵심값 | 비고 |
|---|---|---|
| VLM Qwen3-VL-8B | NF4 4bit, `max_new_tokens=1000`(⚠️스펙 4000에서 검증모드로 낮춘 상태) | Turing GPU: fp16/4bit만, bf16 불가 |
| STT faster-whisper-large-v3-turbo | fp16, language=ko | 사전 실측 기반 결정 |
| LLM Qwen2.5-14B | NF4 4bit, `max_new_tokens=500`(⚠️스펙 2048에서 낮춘 상태), `temperature=0.2` | vLLM→hf_transformers 전환(인프라 제약) |

두 모델의 `max_new_tokens`가 아직 "검증 통과 우선"용 축소값에 머물러 있고, evidence 태깅 신뢰도 이슈가 먼저 해결돼야 스펙값으로 복구 예정(계획서 §6 규칙).

## 7. 최종 산출물

3종을 단계별 폴더에 분리 저장: `transcripts/<video_id>.json`(STT), `output/vlm_observations/<video_id>.observations.json`(VLM 원시 관찰, 디버그용), `output/tacit_json/<video_id>.tacit.json`(최종 스키마 v1.3). 전부 `ensure_ascii=False, indent=2`.

**최종 JSON 핵심 구조**: `candidates[].knowledge = {situation, tacit_insight, reasoning, reasoning_origin(utterance/model_inferred), diagnostic_steps[](order, action, evidence(utterance/action_only), source_utterance, timestamp), conflict/conflict_detail}`. `metadata`(id, source 등)는 전부 시스템이 자동 채움.

## 8. 면접 꼬리질문 대비 — 코드가 인정한 한계

1. `vlm.params.input_mode`는 코드에 안 쓰이는 죽은 설정값
2. YOLO는 프레임 배치 추론이 아니라 프레임별 순차 호출(미최적화 지점, 정직하게 인정 가능)
3. `FrameMeta.fps`가 실제 영상 fps가 아니라 30.0 하드코딩 폴백(현재 사용 경로엔 영향 없지만 TODO로 남음)
4. VLM/LLM `max_new_tokens`가 아직 스펙값 대비 축소된 "검증모드" 상태
5. LLM의 시간·근거 판단을 원천적으로 못 믿어 코드가 사후 강제 정정하는 구조 자체가, 로컬 sLLM의 시간 정합성 추론이 아직 불안정하다는 방증
