## 어떻게 동작하나

|     | 단계            | 하는 일                                                   |
| --- | --------------- | --------------------------------------------------------- |
| 1   | **영상 수집**   | 명장의 1인칭(Egocentric) 작업 영상                        |
| 2   | **STT**         | 명장이 *말한 것*을 받아 적는다                            |
| 3   | **VLM**         | 명장이 *한 것*을 관찰해 적는다                            |
| 4   | **정렬 + 융합** | 말과 행동을 타임스탬프로 묶고, LLM이 암묵지 후보를 서술   |
| 5   | **품질검증**    | 매뉴얼에 이미 있는지, 근거가 실제 발화에 붙어 있는지 심사 |
| 6   | **지식 DB**     | 통과한 지식만 임베딩해 Vector DB 적재                     |
| 7   | **활용**        | 신입이 음성으로 질문 → 근거·출처와 함께 답변              |

**핵심은 4번과 5번입니다.** 암묵지는 "말한 것"에도 "한 것"에도 온전히 없고 그 사이에 있어서, 둘을 시각으로 붙여야 나옵니다. 그리고 뽑아낸 게 진짜 노하우인지는 **매뉴얼과 대조해야** 알 수 있습니다.

## 설계 1 — 말과 행동은 동시에 일어나지 않는다

명장은 말없이 작업하다가 한참 뒤에 설명합니다. 그래서 행동 구간에 **±4초 여유**를 주고 겹치는 발화를 끌어옵니다. 그 결과 세 가지 경우가 생기고, **셋 다 후보가 됩니다.**

```
행동 ─────────┐              ┌───── 행동 ─────┐
    ±4s       │              │      ±4s       │        발화만
              │              │                │
   "동시에 눌러야           (침묵)              "닫혔는지
    슬롯이 안 깨져요"                            확인해요"

  Case 1: Action + Voice   Case 2: Action_only   Case 3: Voice_only
```

**Case 2(행동만)가 가장 중요합니다.** 숙련자가 말없이 하는 확인 동작 — 그게 전형적인 암묵지이기 때문입니다.

## 설계 2 — LLM은 서술만 쓰고, 사실은 코드가 채운다

| LLM이 쓰는 것                         | 코드가 채우는 것                 |
| ------------------------------------- | -------------------------------- |
| situation / tacit_insight / reasoning | 타임스탬프, 발화 원문, 절차 스텝 |
| 어느 구간에서 왔는지 (`window_ids`)   | id, 장비명, 출처                 |

LLM에게 절차와 시각까지 맡기면 **없는 단계를 지어냅니다.** 그래서 서술만 맡기고 나머지는 원본에서 재조립합니다.

여기에 태깅 두 개를 강제합니다.

- **`evidence: utterance | action_only`** — 말은 안 했지만 몸으로만 한 행동을 구분
- **`reasoning_origin: utterance | model_inferred`** — LLM이 자기 일반지식으로 채운 설명을 **발화 근거인 척 위장하지 못하게** 강제

## 설계 3 — 매뉴얼에 있으면 암묵지가 아니다

후보를 4단계로 심사합니다.

**① 타임스탬프 유효성** — 인용한 발화가 클립 구간에 실재하는가 (행동만 있는 스텝은 면제)

**② 매뉴얼 대조 (Gate A)** — 후보 키워드로 매뉴얼을 검색(Top1 유사도 ≥ 0.65)한 뒤 LLM이 판정

| 판정    | 의미                      | 처리       |
| ------- | ------------------------- | ---------- |
| `same`  | 매뉴얼에 이미 있음        | **reject** |
| `delta` | 상황은 같은데 행동이 다름 | 통과       |
| `novel` | 매뉴얼에 없는 상황        | 통과       |

> 실제 delta 사례 — 매뉴얼 5장은 "RAM 탈거 → 재장착"을 절차로만 규정합니다.
> 명장은 **양쪽 래치를 동시에 눌러** 분리하며 "그렇지 않으면 파손될 수 있습니다"라고 말합니다.
> **상황은 일치, 행동은 매뉴얼에 없음 → delta.** 이게 암묵지입니다.

**③ 근거성 채점** — LLM Judge가 4개 항목을 독립 평가

| 항목                        | 무엇을 보는가                 |
| --------------------------- | ----------------------------- |
| `reasoning_grounding`       | 이유가 실제 발화에 접지됐는가 |
| `step_grounding_ratio`      | 절차가 원문과 일치하는가      |
| `action_reason_consistency` | 행동과 이유가 맞물리는가      |
| `utterance_signal`          | 발화에 노하우 신호가 있는가   |

**④ Confidence 산출**

```
C = 0.35·reasoning_grounding + 0.30·step_grounding_ratio
  + 0.20·action_reason_consistency + 0.15·utterance_signal

C ≥ 0.75 → accept    0.45 ≤ C < 0.75 → hold    C < 0.45 → reject
```

가중치는 고정값이 아니라 **전문가 라벨 100건 이상 축적 시 로지스틱 회귀로 자동 전환**되도록 설계했습니다. 임계값도 Precision-Recall Curve 기반으로 재산출됩니다. 더미 라벨 60건으로 이 절차를 사전 검증했습니다.

## 결과 — SKILL-X vs 일반 LLM

질문: _"컴퓨터 전원이 켜지지 않고, 전원 표시등이 황색으로 여러 번 깜빡이는데 왜 이러죠?"_

|             | 답변                                                                                                                                                                                                                                                       |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ChatGPT** | "제조사가 어디인가요?" → RAM/PSU/메인보드/CPU 등 일반적 원인 나열 → 방전 후 재부팅                                                                                                                                                                         |
| **Gemini**  | LED는 경고 신호라는 설명 → 방전 → RAM 재장착 → 깜빡임 횟수 확인                                                                                                                                                                                            |
| **SKILL-X** | **황색 4번 → 백색 5번이면 RAM 오류.** 해당 모델은 슬롯이 6개이며 색상으로 채널 구분. 양손 검지와 엄지로 **슬롯 양쪽 래치를 동시에 누르며** 탈거. **한쪽만 강하게 누르면 슬롯이 손상**됩니다.<br>출처: CLIP4 (00:01:55–00:02:49), CLIP1 (00:02:34–00:03:18) |

차이는 세 가지입니다 — **이 장비의 LED 코드를 안다**, **손가락 단위로 어떻게 하는지 안다**, **어느 영상 몇 초에서 온 지식인지 출처가 붙는다.**

무관한 질문(`"오늘 날씨 어때요"`)에는 0.157초 만에 "관련 암묵지를 찾지 못했어요"로 응답합니다. 유사도 임계값 미만이면 **LLM을 호출조차 하지 않습니다.**

## 왜 이 모델을 골랐나

모든 선정은 동일 데이터셋·동일 조건 비교 실험을 거쳤습니다.

### 구간 추출 — Dataset-Adaptive Motion Sampling (자체 제안)

작업 영상은 대부분이 정지 구간이라 균일 추출이 비효율적입니다. 세 기법을 비교하고, 데이터셋 특성에 따라 자동 선택하는 스코어를 설계했습니다.

```
Motion Score = 0.40·Coverage + 0.35·(Motion Relevance/100) + 0.25·Uniformity
```

| 기법           | 종합점수  | 특성                               |
| -------------- | --------- | ---------------------------------- |
| **MG Sampler** | **0.738** | 작업 패턴 변화에 최적화 → **채택** |
| AKS Window     | 0.673     | 전체 시퀀스 보존에 적합            |
| Threshold      | 0.525     | 고모션 데이터에 적합               |

전체 652초 → 495초(**유지율 75.9%**), 829MB → 547MB

```
기본 Prompt              →   최적화 Prompt
"GPU를 오른손으로            "RAM을 오른손으로 잡아 정렬한다
 슬롯에 삽입한다"             RAM을 슬롯에 삽입한다
"GPU를 오른손으로            양 엄지로 가압하여 장착을 확인한다"
 슬롯에 삽입한다"  (반복)
```

**모델보다 임베딩 대상을 바꾼 게 더 효과적이었습니다.** `tacit_insight` 단독으로는 신입의 증상 질의("화면이 안 떠요")와 유사도가 0.27대에 그쳤는데, `situation + tacit_insight + reasoning` 합본으로 바꾸자 0.44~0.61로 올랐고 **Recall@3이 9/9(1.00)** 가 됐습니다.

## 기술 스택

```
영상  →  YOLO11m  +  Qwen3-VL-8B        (객체 탐지 · 행동 관찰)

융합  →  Qwen3-14B                      (암묵지 후보 생성)
검증  →  LangGraph 4-Gate + Manual RAG   (신규성 · 근거성)
저장  →  BGE-M3 + Vector DB              (임베딩 · 검색)
활용  →  FastAPI + Qwen3-14B + SuperTonic TTS  (음성 RAG)
```

전 모델 오픈소스·로컬 구동. 외부 API 호출 0회, 데이터 유출 없음.
